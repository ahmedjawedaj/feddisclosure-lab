# v0.15 external baselines (WP11, checks B1 and B2)

Question: are the repository's own attacks weaker than established external implementations on a matched setup? Thresholds are fixed in `docs/preregistration/v0.15.md` and were not changed.

| Check | Rule | Result |
|---|---|---|
| B1 inversion | repo mean MSE at most 1.5 times the external baseline MSE | **FAIL** against the tuned breaching configuration (ratio 1.86). PASS against the two as shipped library configurations |
| B2 membership | repo AUC at least reference AUC minus 0.03 | **PASS** (repo 0.7416, strongest reference 0.7401) |

Machine readable verdicts: `reports/results/privacy/v0150/prereg_check_external.json`. Details and per seed data: `reports/results/privacy/v0150/external/`.

## B1 setup

Matched to `scripts/run_view_comparison.py`. Digits (sklearn, 1797 records), 4 clients with 8 records each, record selection by `select_view_records` (seed 1000 + s), victim is client 0, `DigitMLP` 64 in and 10 out, one local full batch SGD step at lr 0.15, the attacker sees the victim's plaintext individual update and knows the labels, the initial model and the learning rate. The gradient handed to every attack is (initial weights minus final weights) divided by lr, which is exactly what the repo attack computes internally. Both attacks therefore receive the same numbers. Scoring is the repo's own `score_victim` (optimal MSE matching, evaluator side) for both attacks. Recognisable share is the share of victim records with MSE below 0.05. 20 evaluation seeds (0 to 19, the saved v0.14.2 study used 0 to 9). Interval type: percentile bootstrap over seeds, 10000 resamples.

The repo attack is `view_study.attack` with the saved setting (300 Adam iterations, lr 0.12, TV weight 0.0005, initial images uniform in [0.2, 0.8], seed + 1).

External attack: `breaching` 0.1.2 (Geiping et al.), library classes called directly through `breaching.attacks.prepare_attack` on the same model and gradient, labels passed in so the library's label recovery is not used. Library configurations used:

* `ig_library_default`: the shipped `invertinggradients` yaml unchanged. Cosine similarity objective, Adam, signed gradients, step size 0.1 with step-lr decay, box constraint, total variation 0.2, 24000 iterations, random normal initialisation. This is the Inverting Gradients attack (Geiping et al. 2020) as the library ships it.
* `dlg_known_labels`: the shipped `deepleakage` yaml (Euclidean objective, L-BFGS, 1200 iterations) with `attack_type=optimization` so that labels are not optimised, because the repo attack knows them. This is the DLG objective (Zhu et al. 2019) with the iDLG advantage of known labels.
* `tuned_ig_tv0.001`: the `invertinggradients` yaml with 4000 iterations and total variation scale chosen on tuning seeds 9000 to 9002. Candidates were TV scale 0.2, 0.05, 0.01, 0.001, 0 (4000 iterations each) and `dlg_known_labels`. The lowest mean MSE on the tuning seeds was TV 0.001 (0.0069, next best TV 0 at 0.0107). Evaluation seeds were not used for the choice. The rule "the headline external baseline is the tuned configuration" was fixed in `scripts/run_external_baselines.py` before the evaluation seeds were run, because a baseline left at defaults that are poorly suited to 8x8 digits is a weak baseline.

Adaptations needed to run an image library on a 64 feature MLP (none changes the weights, the gradient or the loss):
* the digit is shown to the library as a 1x8x8 image and the model is wrapped to flatten it,
* the library's total variation regulariser is built for three colour channels, so its fixed difference kernel was cut to one channel (same kernel, same scale),
* data normalisation is the identity (mean 0, std 1), so the box constraint is the pixel range [0, 1].

## B1 results (20 seeds, 8 victim records per seed)

| Attack | Mean MSE (95% bootstrap CI) | Recognisable share | Seconds per seed |
|---|---|---|---|
| Label only floor (class average image of the public pool) | 0.0423 (0.0390 to 0.0458) | 0.738 | 0 |
| Repo gradient matching | **0.0115** (0.0080 to 0.0154) | 0.956 | 0.3 |
| breaching, `ig_library_default` | 0.0482 (0.0428 to 0.0536) | 0.731 | 52 |
| breaching, `dlg_known_labels` | 0.0246 (0.0171 to 0.0323) | 0.850 | 20 |
| breaching, `tuned_ig_tv0.001` | **0.0062** (0.0040 to 0.0087) | 0.994 | 9 |

B1 ratios (repo MSE divided by external MSE, pass at most 1.5). The ratio of mean MSE is 1.86 for the headline configuration, with a 95% percentile bootstrap interval over seeds of [1.47, 2.51] (10000 resamples, bootstrap seed 0, recomputed from `external/inversion/seed*.json` and now written by `summarise-inversion` as `ratio_bootstrap_ci95`). The interval lies entirely above the 1.5 limit, but only just at its lower end. Per-seed ratios are dominated by three seeds near 10 times (0.0173 against 0.0016 at seed 5, 0.0130 against 0.0013 at seed 16, 0.0152 against 0.0019 at seed 0, ratios 10.7, 10.2 and 8.0). The median per-seed ratio is 1.55.

| External configuration | Ratio | Verdict | Paired MSE difference repo minus external (95% CI) | Seeds where repo is lower |
|---|---|---|---|---|
| `ig_library_default` | 0.24 | PASS | -0.0367 (-0.0408 to -0.0328) | 20 of 20 |
| `dlg_known_labels` | 0.47 | PASS | -0.0131 (-0.0198 to -0.0065) | 17 of 20 |
| `tuned_ig_tv0.001` (headline) | 1.86 | **FAIL** | +0.0053 (+0.0030 to +0.0079) | 3 of 20 |

Reading. Our attack is much stronger than breaching as the library ships it, and its recognisable share (0.956) is well above the label only floor (0.738). A breaching Inverting Gradients attack with a lighter total variation penalty is stronger than ours, with about half the MSE and a recognisable share of 0.994. The paired difference is positive in 17 of 20 seeds and its interval excludes zero, so this is not seed noise. By the pre-registered rule the repo inversion attack is weaker than the external baseline, and B1 is recorded as FAIL. In absolute terms both attacks recover most records on this setup (one exact gradient, 8 records, a small MLP), so the gap changes the strength of the conclusion about how much an attacker gains, not whether a plaintext update leaks. The plaintext gap is about 0.005 MSE (paired difference +0.0053). A stronger inversion was not run on the aggregate or protected views, so the aggregate-at-floor claims are conditional on the weaker attack. Whether the gap would also show on those views is untested. The S1 pass at 8 clients in `docs/v0.15-scaling.md` is one of those claims. It is a vacuous pass (the aggregate is far below the floor), so it says this attack is weak and is not privacy evidence.

Caveats. The tuned breaching configuration got a small search (six candidates, three tuning seeds) and the repo attack got none in this work package, so the comparison favours breaching. The tuned configuration was not equalised on iterations either (4000 versus 300). Whether a tuned repo attack closes the gap was not tested here.

## B2 setup

Matched setting: the saved shadow and target models of `reports/results/privacy/v014/lira/large_overfit/` (Digits, pool of 360 records, three site federated training, 40 rounds, 10 local epochs, no DP). 64 shadow models and 16 target models, each trained on a random half of the pool. The reference LiRA scores exactly the same 64 shadows and 16 targets from the saved logit scaled confidences (`scores.npz`), so shadow models are identical by construction. No model was retrained.

Search for an installable LiRA:
* `mialibrary` 0.1.5 (PyPI, "A simple library to conduct LiRA from Carlini et al. (2022) and RMIA"). Pure score computation from precomputed shadow statistics. Installable, used here as the reference. It is a small and young package, which is a limitation of calling it established.
* `privacy-meter` 1.0.1 (MIT) is installable but its PyPI release has population, reference and Shokri style shadow metrics and no LiRA online scoring. Not used.
* `tensorflow-privacy` 0.8.11 needs TensorFlow, and its PyPI wheel does not contain the `advanced_mia` LiRA module. Not used.
* `leakpro` 0.0.1 and `lira` 0.0.1rc1 on PyPI are placeholders without an attack implementation.

So one maintained installable LiRA was found (`mialibrary`). In addition an independent reimplementation of the online LiRA scoring was written from the paper (`independent_lira_scores`). It is a cross check and not an external baseline. It agrees with `mialibrary` to 1e-14 on every variant here (`agreement_independent_vs_mialibrary` in `lira_summary.json`) and to 1e-8 in a unit test.

`mialibrary.lira.simple_lira.run_simple_lira` was called with only the 64 shadow models, in four variants: centre mean or median, per example or global standard deviation. The repo number is the repo's own `lira_scores` (per example variance with the repo's variance floors) applied to the same models. AUC is the mean over the 16 targets. Interval: two level percentile bootstrap (resample targets, then resample members and non-members inside each target), 2000 replicates. Paired differences use the same resamples.

## B2 results

| Attack | Mean AUC | 95% bootstrap CI |
|---|---|---|
| Repo LiRA | 0.7416 | 0.7258 to 0.7577 |
| mialibrary, mean, per example variance | 0.7401 | 0.7238 to 0.7563 |
| mialibrary, mean, global variance | 0.7323 | 0.7141 to 0.7503 |
| mialibrary, median, per example variance | 0.7329 | 0.7157 to 0.7505 |
| mialibrary, median, global variance (the library's documented recommendation) | 0.7277 | 0.7078 to 0.7470 |

Headline reference: the strongest `mialibrary` variant by mean AUC, which is the most demanding choice for the repo and was fixed in the script before the comparison. It is also the like for like variant (mean, per example variance). Repo minus reference AUC is +0.0015 (paired 95% CI -0.0003 to +0.0035). Pass requires at least -0.03. **B2: PASS.** Against the other three variants the repo AUC is higher by +0.009 to +0.014, with paired intervals that exclude zero. The repo LiRA is not weaker than the reference on this setting.

## What the comparison does and does not show

* It shows that on one matched setting each repo attack is, or is not, within the pre-registered margin of one external implementation. It does not show that the repo attacks are optimal, nor that other external attacks (analytic, recursive, malicious server) are no stronger.
* B1 covers one gradient inversion setting (plaintext update, one local step, 8 records, known labels, small MLP). It says nothing about the protected views, multi step updates or larger batches.
* The breaching result depends strongly on its configuration. Between the shipped Inverting Gradients setting and the tuned one the MSE changes by a factor of eight. Any single "external baseline" number is therefore a statement about a configuration. All three are reported.
* B2 compares scoring rules on the same shadow models. It does not test shadow model training, which the reference library does not provide. It covers the no DP overfit regime only, where LiRA is strong (AUC 0.74). It does not cover the DP regimes where all attacks are near 0.5, so it cannot show whether the attacks agree there.
* `mialibrary` is a small and young package, so agreement with it is weaker evidence than agreement with a long maintained reference would be. The independent reimplementation agrees with it exactly, which supports the scoring being a faithful standard LiRA but is not independent of the same reading of the paper.

## Reproduction

Isolated environment, see `requirements-external.txt`. The main environment (torch 2.15.0+cpu, numpy 2.5.3, flwr, opacus) was not modified. `torchvision` from PyPI is a CUDA build that does not load against the CPU torch, so the CPU build (0.29.2+cpu from the PyTorch index) is installed in the venv only.

```
EXT_PY=/path/to/isolated-venv/bin/python
PYTHONPATH=src:. "$EXT_PY" scripts/run_external_baselines.py tune
PYTHONPATH=src:. "$EXT_PY" scripts/run_external_baselines.py inversion --max-seconds 420   # resumable
PYTHONPATH=src:. "$EXT_PY" scripts/run_external_baselines.py summarise-inversion
PYTHONPATH=src:. "$EXT_PY" scripts/run_external_baselines.py lira
PYTHONPATH=src:. "$EXT_PY" scripts/run_external_baselines.py check
```

Runtime on 2 shared CPUs: tuning about 9 minutes, inversion about 28 minutes (the library default configuration is 52 seconds per seed), LiRA about 7 minutes. Tests: `pytest tests/training/test_external_baselines.py` (22 pass in the main environment, 26 in the venv where the `mialibrary` agreement tests also run).

`check` rebuilds `prereg_check_external.json` from the saved stage outputs and reproduces the committed `checks` block exactly. The bootstrap note on the B1 headline is a constant in the script (`RATIO_NOTE`) and no longer needs a hand edit. The `versions` block comes from the packages installed where `check` runs. A package that is not installed there (for example `breaching` in the main environment) keeps the version recorded in the saved file and a `versions_note` names it, so a rerun does not replace it with null. A test regenerates the `checks` block and compares it with the committed file.
