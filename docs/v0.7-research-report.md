**Date:** 2026-11-19. **Scientific status:** Exploratory reproducibility study and an optional native OpenDP query adapter. Not a thesis novelty or a completed native Docker/Flower/DP certification.

## RQ: When local optimizer budgets are matched, how does partition heterogeneity affect utility?

Protocol and preselected configurations: [`v0.7-pre-registered-protocol.md`](v0.7-pre-registered-protocol.md). The first seeds were 241–243; seeds 244–245 were explicitly added before their runs as an exploratory replication. All 20 runs are retained. Dataset is 900 selected public scikit-learn 8×8 digit examples per seed, 180 held out globally and 720 distributed to 3 institutions. The same selected and held-out source indices are used within each seed. Each institution receives exactly 192 train and 48 validation records. Three independent CPU PyTorch workers use FedAvg for four communication rounds, two local epochs and batch size 32, with 12 minibatches per site per round. This is not a native Flower run.

| Partition | Mean global held-out accuracy ± sample SD | Mean worst-client validation accuracy ± sample SD | Mean client-label TV distance |
|---|---:|---:|---:|
| IID | 68.89% ± 2.83 pp | 65.00% ± 2.28 pp | 0.0675 |
| Balanced Dirichlet α=0.1 | 71.22% ± 4.64 pp | 53.33% ± 18.20 pp | 0.4023 |
| Balanced Dirichlet α=0.5 | 67.67% ± 6.42 pp | 60.00% ± 9.25 pp | 0.3816 |
| Balanced Dirichlet α=10.0 | 71.56% ± 4.38 pp | 65.42% ± 4.80 pp | 0.1160 |

Averaged over five matched seeds, relative global accuracy compared to IID was +2.33 percentage points for α=0.1, −1.22 pp for α=0.5, and +2.67 pp for α=10.0. The effects were not monotonic across the prescribed α values. The severe α=0.1 condition had a **lower worst-client mean** (53.33% versus IID 65.00%) and a much larger between-seed sample SD of 18.20 pp versus 2.28 pp. This is a descriptive pilot, not a statistically significant causal effect or generalization to medical records.

**Crucial difference from v0.6:** The old unconstrained Dirichlet allocator gave clients unequal sample counts and optimizer work; comparing 82.78% to 63.33% from those runs was confounded. The new capacity-weighted allocator enforces matched volumes and local updates and does not reproduce that simplistic interpretation. However, changing the label composition also changes validation difficulty across institutions; matching sample budgets does not eliminate all confounders. α is the *sampling preference* and the evaluator-measured label TV should be reported instead of assuming strict monotonicity in heterogeneity.

**Reproduction:** `python scripts/run_balanced_heterogeneity.py --seeds 241 242 243 244 245 --rounds 4`, `python scripts/plot_balanced_heterogeneity.py`, and `python scripts/verify_v070_evidence.py`. The last command checks all 20 model checkpoint SHA-256 hashes, immutable private-site partition hashes, disjoint index sets, matched test cohorts, local optimizer steps, communication, and scalar summary recomputation.

**Figure:** `reports/figures/sprint5_balanced_heterogeneity.png`. Full per-seed values and curves are in `reports/results/sprint5/balanced_heterogeneity/summary.json`. There are five true **training** seeds, not merely test-query samples.

## D1: DP analytics adapter and HTTP transport (runtime blocked)

The code now includes a site-local OpenDP scalar count adapter, fixed-point SQLite epsilon ledger, independent cross-experiment budget scope, an opt-in `FDL_DP_ENABLED=1` protected mode and a gateway `/v1/federated-dp-count` route. Protected mode disables existing unprotected analytics endpoints and cannot reuse a database with prior unprotected query activity; a database that has spent a DP budget cannot silently downgrade to the unprotected mode. Site budgets are transactionally reserved and rolled back on measurement failure. Refusals return no raw site counts or partial gateway results. **The tests exercising the HTTP and ledger path deliberately inject a fake measurement for transport/transaction testing. They do not demonstrate DP.** Concurrent budget accounting and budget-reset attempts are regression-tested.

The actual mechanism uses **OpenDP**, not a custom Laplace sampler. It checks the OpenDP privacy map under add/remove-one adjacency with per-site sensitivity 1. The requested pure-DP epsilon=0.25/query and site total budget=1.0 are settings for a *future native* smoke run. No actual OpenDP noise, statistical error tradeoff or formal privacy guarantee has been measured in this environment: `opendp` is unavailable and the native runner explicitly exits nonzero without writing an artifact. See [`opendp-runtime.md`](opendp-runtime.md).

**Important:** Cross-site partial failures may expend some individual-site privacy budget while rejecting the overall gateway response. A production system would also need authorization/account boundaries, operational key and dataset governance, failure handling, hardened storage isolation and a reviewed cross-site accounting approach. This proof-of-concept does not protect an analytics user who previously saw raw counts from the unprotected research-mode gateway.
