# v0.16 P3 Colab runbook: breaching on CIFAR-10

Pre-registration: `docs/preregistration/v0.16-p3.md`. Script: `scripts/p3_breaching_cifar10.py`.
Target runtime: Colab with a Tesla T4 (15 GB), torch 2.14.1+cu130 and a matching torchvision preinstalled. Do not reinstall torch.

Nothing in this runbook changes a pre-registered parameter. The only flags that matter for the real run are `--out`, `--data-dir`, `--seeds 20` and `--device`. Do not pass `--quick` for the real run, because a quick run writes no verdicts.

## What you need

* The script file `scripts/p3_breaching_cifar10.py` from this repository, at the commit that holds the pre-registration and the script.
* A Google Drive folder for the output, for example `MyDrive/feddisclosure_p3`. Seed files are written there one at a time, so a disconnect loses at most the seed in progress.
* About 700 MB of local disk on the runtime for the CIFAR-10 download and cache. It goes to `/content`, not Drive.

## Where the files land

All in `/content/drive/MyDrive/feddisclosure_p3/out/`:

| File | Content |
|---|---|
| `model.pt` | the shared CNN checkpoint, its SHA-256 and held-out accuracy |
| `tuning_seed9000.json` to `tuning_seed9002.json`, `tuning.json` | PSNR of every grid point and the selected total variation settings |
| `seed0.json` to `seed19.json` | one file per evaluation seed, per image MSE, PSNR and SSIM for every row, the label-only floor attached to every row |
| `images_seed0.npz`, `images_seed1.npz` | originals and reconstructions of the first two seeds, for a visual check |
| `summary.json` | seed-level bootstrap intervals, the pre-registered verdicts K0, R1, R2, R3, R1r, R2r, R3r, B1c, O1, O2, and the observed seed standard deviation next to the power assumption |

The CIFAR-10 cache stays in `/content/p3_data` and is lost with the runtime. The model and tuning files are on Drive, so a resumed run does not retrain or retune.

## Resuming after a disconnect

Run cells 1, 2, 3 and 4 again, then run the cell 6 command unchanged. The script skips every seed whose JSON is present and complete, reuses `model.pt` and `tuning.json`, and redoes a seed whose file is missing or was cut off. A seed file written under different settings is refused with a message, and in that case use a new `--out` folder. Do not delete `model.pt` or `tuning.json` between sessions. Retraining on a different GPU would give a slightly different model, and the script would then refuse the old seed files, which protects against mixing models.

To rebuild only the summary from the existing seed files:

```
!python /content/p3_breaching_cifar10.py --stage summarise --seeds 20 --out /content/drive/MyDrive/feddisclosure_p3/out
```

## Runtime estimate

The estimate comes from timings on the 2 vCPU CPU container where the script was smoke tested, scaled to a T4. The T4 number is an assumption and was not measured.

Measured on CPU (seconds per attack iteration, trained CNN, real CIFAR-10 batch): breaching 0.0102 for a batch of 8, 0.0252 for a batch of 32, 0.0061 for a batch of 1. Repository attack 0.0081 (batch 8) and 0.0215 (batch 32). Model training took 95 seconds for 10 epochs on 20,000 images.

Iteration counts per evaluation seed: breaching 4 x 4,000 for the control, 3 x 4,000 on batches of 8 (plaintext, collusion, collusion at `max_weight` 16), 2 x 4,000 on batches of 32 (aggregate and exact aggregate), 24,000 for the library default row. Repository attack 3 x 3,000 on batches of 8 and 3,000 on a batch of 32. Tuning per seed: 12 breaching and 12 repository runs of 4,000 and 3,000 iterations.

| Item | CPU timings | T4 assumption of 6 ms per iteration whatever the batch |
|---|---|---|
| One evaluation seed | about 13 minutes | about 7 minutes |
| 20 evaluation seeds | about 4.5 hours | about 2.4 hours |
| Tuning, 3 seeds | about 1 hour | about 25 minutes |
| Model training | 1.5 minutes | under 1 minute |
| Data download and parse | 15 seconds (Hugging Face) | similar |
| Total | about 5.5 hours | about 2.8 hours |

A T4 runs a tiny network at launch bound speed, so 6 ms per iteration is a guess that the CPU timings do not settle. The first finished seed gives the real number. Read `seconds_total` in `seed0.json` and multiply by 20, then add the tuning time shown in the log. Free Colab sessions often end after a few hours, so expect to resume at least once if the T4 turns out slower than the guess.

## Known risks on the GPU run

* The Colab stack (torch 2.14.1 with CUDA 13) was not available when the script was tested. The library uses `torch.jit.script` in its objectives. If cell 5 fails inside `breaching`, copy the traceback and stop before the full run.
* `breaching` returns whatever it has when its objective turns non-finite. The script counts these in `invalid_reconstructions` and does not retry.
* GPU results are not bitwise reproducible. A rerun can differ in the last digits.
* If the downloaded Hugging Face parquet hash differs from the pinned one the script stops. Pass `--allow-data-hash-mismatch` only after checking why, and record the new hash in the deviation log.
