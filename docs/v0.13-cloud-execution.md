# v0.13 cloud execution: what ran and what did not

Execution date: 2026-11-20 (UTC). This is **not** the Docker/Flower certification milestone.

## Actual executed experiment

This container provides PyTorch but does not provide Docker CLI/daemon, Flower, a
reachable Python package index, or a cloud-VM provisioning interface. Linux
unprivileged user/mount/PID namespaces *are* available. We therefore ran an
**additional research fallback** that provides real OS namespace isolation
without suggesting it qualifies as Docker or Flower.

- Three independent `unshare --user --map-root-user --mount --pid --fork`
  PyTorch workers trained in parallel during each of two FedAvg rounds.
- Each worker bind-mounted only its own prepared public `sklearn_digits`
  training and validation files read-only.
- The staged dataset root was masked by a private tmpfs, hiding all three
  original partition paths; the inherited host `/proc` was masked as well.
- Per-round receipts record three distinct user, mount, and PID namespace IDs,
  read-only mount verification, and a digest of the sole visible dataset.
- A trusted host coordinator combined only model weights and sample counts.
  A separate evaluator process used the public held-out test set.
- Result: round 1 global accuracy **15.00%**, round 2 **20.83%**.
- An independent standard PyTorch run on the same partitions also finished at
  **20.83%**. Numerical checkpoint parity passed at `atol=rtol=1e-6` with a
  maximum tensor difference of `1.4901161193847656e-08`.
- Six client-round isolation receipts, a model checkpoint, a reference
  checkpoint, and a verification report are saved with the release archive.

Namespace isolation is limited: host-root/orchestrator can access raw datasets,
shared model-update scratch space remains available to client processes, and
this does not establish security against host-root or kernel adversaries. It
provides no secure aggregation or differential privacy guarantee. The Linux
kernel's ability to run namespaces does **not** certify a Docker deployment.

## How to reproduce on a host permitting unprivileged namespaces

```bash
python -m pip install -e '.[test,research]'
PYTHONPATH=src:. python scripts/run_linuxns_reference.py \
  --data-dir data/training/digits-namespace-iid-v013 \
  --output-dir reports/results/linux_namespace/v013
PYTHONPATH=src:. python scripts/run_torch_reference.py \
  --config configs/training/fedavg_digits_iid.yaml \
  --data-dir data/training/digits-namespace-iid-v013 \
  --output reports/results/linux_namespace/v013/torch_reference.json
PYTHONPATH=src:. python scripts/verify_linuxns_reference.py \
  --data-dir data/training/digits-namespace-iid-v013 \
  --output-dir reports/results/linux_namespace/v013
```

Use **fresh output directories** for independent runs. The archive includes
snapshots of the public data and evidence; the Git repository intentionally
excludes raw partitions and model checkpoints.
