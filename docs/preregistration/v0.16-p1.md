# v0.16 P1 pre-registration: audit of Flower's differential privacy mechanisms

Status: written before any audit run in this phase. Date: 2026-11-23.
Subject: `flwr` 1.27.0 (the version pinned by this repository). Results will be re-checked on a newer release and any difference reported.

## Question

For each differential privacy mechanism that Flower ships, does the privacy level a user would compute from the configured parameters match the privacy level of the mechanism that actually runs?

This is a measurement of one framework version under stated configurations. It is not a claim about how Flower is intended to be used. Flower logs a warning in one of the configurations below, and its documentation does not state an adjacency relation or provide an accountant, so "claimed" here always means "what the configured parameters imply under the stated textbook reading", which is defined per row.

## What was already known before this file was written

Stated so that predictions are not presented as blind.

1. The DP source files were read in full before writing predictions. All predictions below come from code reading.
2. The exact delta of the classical Gaussian calibration used by `LocalDpMod` was computed analytically for six epsilon values before this file was written (0.5, 1, 2, 5, 10, 20 at claimed delta 1e-5). Row L1 is therefore confirmatory, not predictive.
3. No mechanism was executed before this file was written.

## Method

Each row runs the real Flower class in process (no reimplementation) on crafted client results with a small float32 parameter vector.

1. Noise-free sensitivity. Run the mechanism with noise multiplier 0 on two neighbouring inputs and take the L2 distance of the outputs.
2. Noise scale. Run the mechanism 20,000 times on a fixed input, estimate the per-coordinate standard deviation, and test normality with a Kolmogorov-Smirnov test.
3. Effective Gaussian parameter. mu = sensitivity / sigma. Exact (epsilon, delta) follows from the Balle and Wang (2018) characterisation: delta(eps) = Phi(mu/2 - eps/mu) - exp(eps) Phi(-mu/2 - eps/mu).
4. Empirical lower bound. Where it has power, a threshold distinguishing test on the projection of the output onto the difference direction, with 200,000 trials per world and 95% Clopper-Pearson bounds, gives a lower bound on epsilon at the claimed delta that makes no Gaussian assumption.

Adjacency for central DP rows is zero-out at the client level: the target client's update is replaced by a zero update, with the number of results unchanged. Replace-one adjacency is reported as a secondary column. Adjacency for local DP is replace-one on a single client's clipped update.

## Detection power

Sensitivity is measured exactly, so any multiplicative deviation above float32 rounding (1e-5 relative) is detected. Sigma from 20,000 draws over 16 coordinates has a relative standard error of about 0.2%, so the 9.5% effect predicted in A1 is about 50 standard errors. The Clopper-Pearson test with 200,000 trials per world can certify epsilon up to about ln(1 / 1.8e-5) = 10.9, which is enough to separate rows C3 and C4 (chosen so that the effective mu is at least 5) from the claimed mu of 1, and is not enough for L1 at epsilon 20. L1 therefore rests on the measured sigma and sensitivity plus the exact formula, and this limit is stated in the results.

## What would count against the predictions

A row is reported as "matches the claim" if measured mu is within 2% of the claimed mu. Any predicted mismatch that measures within 2% of the claim is reported as a failed prediction. No row is dropped.

## Reporting rules

Results are reported as measured values next to configured values. The text does not characterise the framework's behaviour as a defect. Each mismatch row states the configuration needed to reach it and whether the framework warns about it.
