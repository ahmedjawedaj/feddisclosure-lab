# v0.16.9 pre-registration: does TensorFlow Federated deliver the differential privacy noise that its configuration states

Status: written before the script exists and before any noisy call of the aggregator in this phase. Date: 2026-11-26.
Subject: `tensorflow-federated` 0.87.0, the module `tensorflow_federated/python/aggregators/differential_privacy.py` (`DifferentiallyPrivateFactory`, its `gaussian_fixed` and `gaussian_adaptive` constructors), the entry point `tff.learning.dp_aggregator`, and the `tensorflow-privacy` 0.9.0 queries that they call.
Follows: `docs/preregistration/v0.16-p1.md`, `docs/preregistration/v0.16-adaptive-clipping.md` and `docs/preregistration/v0.16-adaptive-guarantee.md` for Flower, and `docs/preregistration/v0.16-nvflare-selection.md` for the power statements.

## Question

Q1. For the Gaussian fixed clipping and Gaussian adaptive clipping aggregators of TFF, does the noise that the aggregator adds to the model update match what the configuration states (the noise multiplier times the clip norm, divided by the configured number of clients), when the number of clients that report equals, exceeds or falls short of that configuration, and when weights are used?

Q2. For adaptive clipping, does the aggregator count the clipped fraction, move the clip and order the clip update against the noise as the configuration and the paper describe, and does the composed noise multiplier of the value sum and the count match the configured total?

Q3. What does TFF report about privacy accounting?

This is a measurement of one framework version under stated configurations. It is not a claim about how TFF is meant to be used. A pass says nothing about other versions, other aggregators in TFF (tree aggregation, distributed DP, secure aggregation records), a trained model, or the privacy guarantee of a whole training run. No epsilon or delta is computed here, because TFF reports a `DpEvent` and no epsilon, and this work does not run an accountant.

Claimed behaviour and where it is written, copied by hand from the installed 0.87.0 and 0.9.0 sources.

1. `gaussian_fixed`, argument `noise_multiplier`: "A float specifying the noise multiplier for the Gaussian mechanism for model updates." The query it builds is a Gaussian sum query with `stddev=clip * noise_multiplier` inside a normalised query with `denominator=clients_per_round`.
2. `gaussian_adaptive`, argument `noise_multiplier`: "Note that this is the effective total noise multiplier, accounting for the privacy loss due to adaptive clipping. The noise actually added to the aggregated values will be slightly higher."
3. `QuantileAdaptiveClipSumQuery`, argument `noise_multiplier`: "The stddev of the noise added to the output will be this times the current value of the clipping norm."
4. `adaptive_clip_noise_params`: the value noise multiplier is `(noise_multiplier**-2 - (2 * clipped_count_stddev) ** -2) ** -0.5`, and `clipped_count_stddev` defaults to `0.05 * expected_clients_per_round`.
5. The tutorial page `federated_learning_with_differential_privacy` on tensorflow.org, as returned by one page fetch and not checked word for word, says that the noise multiplier is the ratio of the noise standard deviation to the clipping norm, that the server adds noise to the sum before averaging, and that "the actual number of clients per round is stochastic with mean clients_per_round".

Neighbouring inputs. The documentation read does not state an adjacency relation. The reading used here is add or remove one client, which for the value sum has sensitivity C (the clip) and for the clipped count has sensitivity 1/2, because the TFP source centres each bit at plus or minus 1/2. Replace-one is reported as a second column where a row can show it. It has sensitivity 2C for the sum.

## Method and statistics

Noise measurement. Clients send zero vectors of 100,000 float32 coordinates, so the expected output is zero and the output is the noise. The statistic is the root mean square over all coordinates of all calls of the row, with known mean 0. With N values its relative standard error is 1 over the square root of 2N. Skewness and excess kurtosis come from the same values. The mean is tested against four standard errors of the mean.

Noise-free checks. A noise multiplier of 0.0 is allowed by the constructors and gives exact arithmetic up to float32 rounding. Differences between outputs are formed in float64. A relative tolerance of 1e-5 is used for all exact checks.

Clip recovery. After one round the new clip is read from the measurement `dp_query_metrics.clip`. The counted fraction is recovered as f = 0.5 minus ln(C1 / C0) divided by the learning rate 0.2, where 0.5 is the target quantile. This uses the geometric update that the constructor sets.

Seeds. The input vectors are drawn with `numpy.random.RandomState(20261126 + 100 * k + j)` for row index k and call index j. `tf.random.set_seed` is called with the same number before each process is created. Whether it controls the noise is row F6, and the prediction there is that it does not, so the noise is not reproducible bit for bit and the saved evidence records one run.

Intervals. Standard errors are normal approximations stated in the Power section. No Clopper-Pearson interval is used because no event probability is estimated except in row A5b, where a binomial standard error is used.

## Power of each null result

A null result here is a statement that a delivered value matches its configured value, or that no dependence is seen. Each entry gives the smallest effect that the check finds with 80% power. For the RMS checks the decision threshold is a fixed tolerance, so a true deviation d is found with 80% power when d is at least the tolerance plus 0.8416 standard errors.

| Null result | Runs | Standard error | Decision threshold | Smallest effect found with 80% power |
|---|---|---|---|---|
| F1, F3, F5 noise RMS, 300,000 values per configuration | 3 calls of 100,000 | 0.129% of the RMS | 0.5% | 0.609% |
| A4 noise RMS, 1,000,000 values per configuration | 10 calls | 0.0707% | 0.5% | 0.560% |
| A6 and A8 noise RMS, 300,000 values | 3 calls | 0.129% | 0.5% | 0.609% |
| A5a count stddev, R 2,000 | 2,000 calls | 1.58% of the stddev | 6% | 7.3% |
| A5c count stddev, R 8,000 | 8,000 calls | 0.79% | 4% | 4.7% |
| A5b clamp share | 2,000 calls | 0.0104 absolute (binomial at 0.3173) | 0.04 | 0.049 |
| A7, n 100 | from A4a and A5a | 0.072% of the composed multiplier | 1% | 1.06% |
| A7, n 12 | from A4b and A5c | 0.55% | 2.5% | 2.96% |
| F6 correlation checks | 100,000 coordinates | 0.00316 | 0.01265 | 0.0153 |
| F1 skewness and excess kurtosis | 300,000 values | 0.00447 and 0.00894 | 0.02 and 0.04 | 0.0238 and 0.0475 |
| Exact checks (F2, F3 noise-free, A3, A6 noise-free, A8 noise-free, F5 noise-free) | one run each | float32 rounding below 1e-6 relative | 1e-5 relative | Any difference above 1e-5 relative on the inputs tried, so power 1 for those inputs |
| A1, A2, F4 value checks | one run each | none | 1e-12, 1e-6 and 1e-5 relative | Any difference above the stated relative tolerance on the inputs tried |
| F6 seed digests | two processes | none | equality of 32 byte digests | Any difference at all |

Effects of the size that matter for the readings in this work are far above these limits. A reading that divides by the reporting count instead of the configured count changes the noise by a factor 2 in F3 and A6. A clip used after its update changes the noise by about 10% in A4. A count that sits at the configured cohort instead of the arrived cohort moves the counted fraction by 0.25 in A6.

The statistics are checked against 4 standard errors for most decision thresholds, so each check has a false failure probability of about 1e-4 when the delivered noise equals the prediction. With about 30 such checks in the script, the chance of at least one false failure in a run is about 0.3%.

Which events, inputs and settings the statements cover. Zero update vectors for the noise rows, a small set of fixed norms for the clip rows, the stated n and m, one TFF version, one platform, float32 vectors of one tensor (and one two-tensor case in F2). They do not cover other norms, a trained model, float64 inputs, ragged inputs, other aggregators, or any claim about the sampling of clients.

Positive controls. F3 check 2 (the count-divided reading), A4 check 2 (the clip after the update), A6 check 3 (the arrived-count reading), F6 check 3 (a correlated vector) and the A3 boundary pair (norm equal to the clip against one float32 above it). Each can register a deviation of the size it is meant to show.

What a pass means. For a row that holds, the delivered value matches the configured one within the stated tolerance for the inputs tried, for TFF 0.87.0. It does not say that the mechanism is differentially private, since TFF states no adjacency, and it gives no epsilon.

## Decision thresholds

1. A row holds when every check in it holds. A check holds when its measured value is inside the tolerance written in Predictions.
2. A mismatch between delivered and configured noise is reported with its ratio. It is called found only when the statistical check fails in both the first run and the one replication. An exact check has no replication.
3. A null result counts as informative only when its smallest effect at 80% power is at most 1% of the quantity for the RMS checks, at most 10% for A5a and A5c, and at most 3% for A7. Otherwise it is reported as uninformative whatever the measured value is.
4. F6 check 4 is a prediction about seeding. If the digests are equal the prediction fails and the row is reported as not held.

## Stopping rule

The number of calls, clients, coordinates and rows is fixed above before the first run. The script runs once in full mode. If a statistical check fails, that row alone is run once more with fresh calls, both results are reported and nothing else is added. No other replication, extra seed, extra configuration or change of tolerance is made after the first full run. Test runs of the script in quick mode go to a temporary directory outside the repository and are not evidence.
