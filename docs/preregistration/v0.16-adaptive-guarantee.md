# v0.16 T8c pre-registration: the effective noise multiplier of the whole adaptive clipping mechanism in Flower

Status: written before the harness exists and before any measurement of this phase. Date: 2026-11-26.
Subject: the four adaptive clipping strategy classes and the four fixed clipping strategy classes of `flwr` 1.27.0 (the version pinned by this repository) and `flwr` 1.44.0.
Reference: Andrew, Thakkar, McMahan and Ramaswamy, "Differentially Private Learning with Adaptive Clipping", arXiv 1905.03871.
Earlier phase: `docs/preregistration/v0.16-adaptive-clipping.md` and `docs/v0.16-adaptive-clipping-audit.md` measured the pieces (bit sign, order of noise and clip update, budget split formula). This phase measures what the pieces give together.

## Question

When Flower runs adaptive clipping over a simulated trajectory of the clip, what noise multiplier does the model sum get in each round, measured against the clip that the clients used in that round, and what multiplier does the composed release (model sum plus noisy clipped count) have when the count is taken with the sensitivity that Flower actually sends?

This is a measurement of two framework versions under stated configurations and stated assumptions. It reports effective noise multipliers and their ratios to the configured value. It does not report epsilon or delta, and it makes no statement about any deployed system.

## What was already known before this file was written

Stated so that predictions are not presented as blind.

1. The earlier phase measured on both versions that the noise of the model sum is scaled with the clip after the round's update (its row A6), that the bit is set for clipped updates (rows A3, A4), that the update rule is the paper's geometric rule applied to the fraction of clipped updates, and that the stored model multiplier follows z_delta = (z^-2 - (2 sigma_b)^-2)^(-1/2) (rows A1, A2). The predictions of rows G2 below follow from those results and are confirmatory in kind. What is new is the trajectory, the clip the clients used, the composition and the grid.
2. The source of `flwr/common/differential_privacy.py`, of the legacy and Message API adaptive and fixed classes and of the two client mods was read in 1.27.0 before this file was written. In 1.44.0 the lines that touch the count were grepped. The code reading says that `adaptive_clip_inputs_inplace` returns `scaling_factor < 1`, that the legacy server side sums these booleans, that the Message API converts the bit with `int(...)` and the client mods send `int(norm_bit)` or the boolean, that the server passes the plain sum of bits to `np.random.normal(count, clipped_count_stddev)` and divides the result by the number of replies, and that no shift by 1/2 or by m/2 appears. Rows G0 test this reading.
3. The paper's treatment of the count was read once during this session through a summarising fetch of the arXiv PDF. Its proof of the guarantee has each user send the pair (clipped update divided by sigma_delta, (b_i - 1/2) divided by sigma_b), so the bit is centred at 1/2 and has magnitude 1/2. It bounds the norm of the pair by S, with S = ((C_t / sigma_delta)^2 + (1 / (2 sigma_b))^2)^(1/2), and sets z = 1/S. Algorithm 1 sets sigma_delta = z_delta C^t with the clip of the round and updates the clip afterwards. The paper states user level privacy with replacement of a user and notes in a footnote that add or remove of a user could be used instead. The paper does not give the reason for the factor 2 in its own words. The reading that the factor 2 comes from the centred bit having magnitude 1/2 is an inference and is labelled unconfirmed. The read was not a line by line comparison with the PDF.
4. No rows of this phase have been run. The timing of one round was measured (a few milliseconds to 30 milliseconds per round at 100 replies) to size the grid.

## Quantities

All quantities are defined for one round t with n = `num_sampled_clients` configured, k replies aggregated, and in every row of this phase k = n (full participation, equal `num_examples` of 1, `FedAvg` inner strategy). Partial participation and unequal weights were covered by the first phase of v0.16 and are not repeated.

1. z: the configured noise multiplier argument. sigma_b: the stored `clipped_count_stddev`. z_delta: the stored `noise_multiplier` of an adaptive object (z_delta = z for a fixed object). q: the target quantile argument. lr: `clip_norm_lr`.
2. C_t: the value of `clipping_norm` on the object immediately before the aggregate call of round t. It is the clip the clients use in round t, because the server side classes clip with it inside the call and the client side classes put it in the config sent to the clients before the call. Row G1 checks this on the output.
3. C_(t+1): the value of `clipping_norm` immediately after the call. r_t = C_(t+1) / C_t.
4. f_t: the noisy count that the object draws, divided by k, read from the draw itself (the harness wraps `np.random.normal` and records the call with a scalar location, which is the count draw).
5. Noise standard deviation on the aggregated average in round t: s_t = compute_stdv(z_delta, C_(t+1), n) = z_delta C_(t+1) / n. This is the value the code uses, because the call adds the noise after the clip update. The noise standard deviation on the sum of the k clipped updates is k s_t.
6. Effective model sum multiplier of round t: zeta_t = k s_t / C_t = z_delta r_t. It is the noise standard deviation on the sum divided by the clip that the clients used. The paper reading of zeta_t is z_delta in every round, because Algorithm 1 uses the clip of the round for the noise.
7. Ratios of round t: rho_delta_t = zeta_t / z_delta and rho_z_t = zeta_t / z.
8. Composed multiplier of round t, for the model sum and the noisy count released together. The count has per user magnitude s_b in the sense of the paper's proof, so its multiplier is sigma_b / s_b. The composed multiplier is Z_t = (zeta_t^-2 + (sigma_b / s_b)^-2)^(-1/2).
   1. Flower reading, s_b = 1. The code sends bits in {0, 1} and passes their plain sum, so one user changes the count by at most 1. Called Z_flower_t.
   2. Paper reading, s_b = 1/2. The paper's centred bit has magnitude 1/2. Called Z_paper_t. At zeta_t = z_delta it equals z by the paper's own relation (earlier row A2).
   3. Ratios Z_flower_t / z and Z_paper_t / z.
9. Equivalent constant multiplier of a trajectory of T rounds: Z_eq = (mean over t of Z_t^-2)^(-1/2). It is the constant multiplier that gives the same sum of precisions over T rounds, which is the Gaussian composition rule without subsampling. It describes the realised trajectory only. It is not a bound over trajectories, because the noise scale of round t depends on the noisy count of the same round.
10. Assumptions behind items 8 and 9, to be repeated in every result table: Gaussian releases, per user contribution bounded in norm as in the paper's proof (add or remove style, model part C_t and count part s_b), no subsampling amplification because all n clients take part, sequential composition of rounds by adding precisions, and the model sum and the count treated as one joint Gaussian in a round with the given zeta_t. If the sensitivity of the count is instead taken as the range of the bit under replacement of a user, the range is 1 for both the centred bit of the paper and the bit of Flower, and the comparison then depends on the sensitivity taken for the model sum (2 C_t under replacement), which this harness does not measure. Both Z_flower and Z_paper are reported so that either reading can be applied. No claim is made about which convention is intended.

## Method

All rows run the real Flower classes in process. The model has 256 float32 parameters, the global model is zero, and a client update is a vector along the first coordinate with a chosen L2 norm. The other 255 coordinates carry no signal, so the output on them is the model noise alone. The global model is not carried between rounds, so a trajectory is a trajectory of the clip under a fixed set of update norms, as in rows A10 and A11 of the earlier phase. No training is run.

1. Update norms in every trajectory: 100 evenly spaced values from 0.5 to 1.5 (median 1.0), n = k = 100, z = 1.0, q = 0.5. These are fixed across rounds.
2. Adaptive grid, per version and per variant V1 to V4: sigma_b in {0.6, 2.5, 5.0, 10.0}, lr in {0.05, 0.2, 1.0}, start clip C_0 in {0.1, 1.0}. That is 24 cells per variant. sigma_b = 5.0 is the default m/20 and is passed explicitly. sigma_b = 0.6 is just above the lower limit z / 2 = 0.5. C_0 = 0.1 is the default and lies below every update norm, so every update is clipped. C_0 = 1.0 is the median of the norms.
3. Per cell: 10 trajectories of T = 30 rounds. In every round the clients use C_t, the harness records the quantities above and then calls the aggregate method once. Total 300 rounds per cell, 7,200 per variant, 28,800 per version.
4. Seeds. `np.random.seed` is set at the start of each trajectory to 20261201 + 100000 a + 10000 b + 1000 c + j, where a, b, c are the zero based indices of sigma_b, lr and C_0 in the lists above and j is the trajectory index 0 to 9. The seed does not depend on the variant or the version. So the four variants and the two versions see the same stream of draws in the same order (count draw first, then model draws, in every class). The agreement between variants and between versions is therefore expected and is not independent evidence. This is stated again in the limits.
5. Client side variants. In the trajectories the bit is the one returned by Flower's own function `adaptive_clip_inputs_inplace` on the same update and the same clip, set on the reply as the mod would set it. The real client mods of both APIs are exercised in rows G0 and G1, where their bits are compared with that function.
6. Fixed grid, per version and per variant F1 to F4: z in {0.5, 1.0, 2.0}, clip in {0.1, 1.0}, 4 trajectories of T = 10 rounds each, same update norms, n = k = 100, seed 20261301 + 1000 a + 100 b + j with a, b the zero based indices of z and clip. Client side classes receive updates already clipped to the clip (the clip does not move, so this does not change the noise), and the real fixed clipping mod is exercised in row G1.
7. Model noise measurement. The measured model noise of a round is the output on coordinates 1 to 255. It is standardised by s_t and pooled. The pooled standard deviation of N standard normal values has a standard error of 1 / sqrt(2 N).
8. The count draw and the model noise draws are recorded by wrapping `np.random.normal` for the duration of one call to the aggregate method. The wrapper forwards to the original function, so the stream of draws is unchanged.
9. Each row records `script_sha256`, the Flower version, the variant and the measured values next to the configured values. Per round raw values of the adaptive trajectories are saved next to the summary.

## Rows and predictions

A row is called held when every measured value is inside its stated tolerance of the prediction. Agreement with the paper reading is recorded separately and does not decide whether the prediction held. Unless a row says otherwise the same prediction applies to all variants and both versions.

### G0 What Flower sends for the count

Configuration: 12 clip values (0.3, 0.5, 0.6, 0.75, 0.9, 1.0, 1.1, 1.25, 1.4, 1.5, 1.6, 2.0) on the 100 norms, z = 1.0, sigma_b = 5.0. For V2 and V4 the replies are produced by the real client mod of the matching API. For V1 and V3 the clipping is done by the class.

| Quantity | Paper reading | Prediction |
|---|---|---|
| G0a. Values of the bit returned by the client mods (V2 and V4) | centred, b - 1/2, so -1/2 or 1/2 | the set of values, taken as numbers, is exactly {0, 1} at the 12 clips, and the bit is 1 exactly when the norm exceeds the clip |
| G0b. Location argument of the count draw (all four) | sum of centred bits | equals the number of norms above the clip, an integer from 0 to 100, with no shift by 1/2 per user and none by n / 2 |
| G0c. Scale argument of the count draw | sigma_b | equals the stored sigma_b exactly |
| G0d. Change of the location when one client moves from inside to outside the clip (100 clients, each moved once, clip 1.0) | 1 (range of the centred bit) | exactly +1 in all 100 cases |
| G0e. Change of the location when one reply is left out (100 cases, k = 99 against n = 100) | 1/2 in magnitude for the centred bit | equals the left out client's bit, so 0 or 1, with the largest magnitude equal to 1 |

From G0d and G0e the sensitivity s_b of the count that Flower releases is 1 under add or remove and the range is 1. The paper's centred bit has magnitude 1/2 and range 1. Tolerance: exact equality for every item.

Detection power: every item is a deterministic comparison with exact values, so a shift by 1/2 or by n / 2 would change the location by at least 0.5 per client or 50 in total and would be detected at the first clip.

### G1 The clip that the clients used

Configuration: z = 0 (noise free path), n = 100, the 100 norms, lr 0.2, clips 0.2, 0.7, 1.0, 1.3, 2.0 set before the round, one round each. Output coordinate 0 is compared with mean(min(u_i, C_t)). For V2, V4, F2 and F4 the replies come from the real mod of the matching API and the clip in the config that the strategy sent is compared with `clipping_norm` before the call. For fixed variants the clip after the call is compared with the clip before.

Prediction: output equals mean(min(u_i, C_t)) with C_t the value before the call, for every clip and variant. Tolerance 1e-5 relative (float32 arithmetic). The config clip equals C_t exactly. For adaptive variants with z = 0 the clip after the call differs from C_t by exp(-lr (f - q)) with f the true fraction clipped.

Detection power: if the clients used C_(t+1) the output would differ from the prediction by 9.5 percent at clip 0.2, about 5 percent at 0.7 and about 1.3 percent at 1.3. It would not differ at clip 1.0 (the fraction clipped is 0.5 there and the clip does not move) and not at clip 2.0 (every update is inside both clips). The tolerance is 1e-5, so the check has power at three of the five clips and none at clips 1.0 and 2.0.

### G4 Measured model noise against the stored scale

Configuration: pooled per variant and per lr, over all 8 cells of that lr (4 sigma_b values and 2 start clips, 80 trajectories of 30 rounds, 255 coordinates, 612,000 values), and separately over the 4 cells of that lr with C_0 = 0.1 (306,000 values). Standardise each round's noise by s_t and take the root mean square.

Prediction: the pooled root mean square is 1 within 0.5 percent over the 8 cells and within 0.7 percent over the 4 cells with C_0 = 0.1, for every variant, version and lr. The pooled standard errors are 0.09 and 0.13 percent, so the tolerances are about five standard errors. The row holds when both pooled values are inside their tolerance.

The alternative reading, that the noise is scaled with C_t and not C_(t+1), would give the pooled value sqrt(mean over rounds of r_t^-2), which is reported next to the measured value for both pools. For the 4 cells with C_0 = 0.1 the alternative gap is 2.5 percent at lr 0.05, 10.5 percent at lr 0.2 and 65 percent at lr 1.0 (r is constant to a few percent in those cells). Detection power: those gaps are 19, 80 and more than 100 pooled standard errors. Over all 8 cells the gap is smaller and not predicted, because the cells with C_0 = 1.0 can have r above 1.

### G5 Fixed clipping variants

Configuration: the fixed grid. Quantities: zeta_t = z exactly, since C_(t+1) = C_t and z_delta = z.

Prediction: the clip after every round equals the clip before (exact equality), zeta_t / z = 1 for every round (exact), the count draw never happens (the recorder holds no scalar location call), and the pooled root mean square of the model noise standardised by z C / n is 1 within 1.5 percent over each variant (6 cells of 4 trajectories of 10 rounds of 255 values, 61,200 values, standard error 0.29 percent, tolerance about 5 standard errors). The composed multiplier equals z, because the fixed classes release no count. The ratios to the configured value are therefore 1.

Detection power: exact comparisons for the clip and the count draw. The noise check detects a deviation of the noise scale of 1.5 percent or more at five standard errors. A smaller deviation of the model noise is not excluded by this row.

### G6 Constructor grid for the budget split

Configuration: for z in {0.5, 1, 2, 4} and sigma_b = k z with k in {0.6, 2.5, 5, 10}, plus z in {0.5, 1, 2, 4, 8} with sigma_b 5.0, build each of V1 to V4 (n = 100) and read the stored z_delta and sigma_b. That is 21 inputs. Compute Z_flower and Z_paper at r = 1.

Prediction: Z_paper / z = 1 within 1e-9 for all 21 inputs and Z_flower / z = (1 + 0.75 (z / sigma_b)^2)^(-1/2) within 1e-9, strictly below 1 for all 21. The ratio gets smaller as sigma_b / z gets smaller.

Detection power: exact arithmetic on stored values. Inputs with sigma_b / z of 10 or more have Z_flower / z within 0.4 percent of 1 and a 1 percent tolerance would not separate them from 1, which is stated in the result table where it applies.

### G7 Agreement between variants and between versions

Prediction: for every cell and trajectory the clip sequences C_0 to C_T of V1, V2, V3 and V4 agree within 1e-9 relative, and the same holds between the 1.27.0 and 1.44.0 runs (compared after both runs). Fixed variants: the model noise standardised values agree between the four variants within 1e-6 relative for the same seeds. Tolerance as stated.

Detection power: the comparison is deterministic and sensitive to any difference above 1e-9. The shared seeds make agreement expected, so a pass shows that the arithmetic is the same and does not show independent confirmation.

## Detection power for the null statements, summary

1. A null here means "the measured value equals the predicted one inside the tolerance". Every null in rows G0 to G7 is listed above with the smallest deviation it can detect. Where a deviation smaller than the stated size could exist, the row does not exclude it.
2. No row tests whether any deviation from the configured multiplier affects a trained model. The harness has no training and no data.

## What would count against the predictions

A row is reported as failed if any measured value is outside its stated tolerance. No row is dropped and no tolerance is changed after a run. A prediction that fails is reported with the measured value. A harness change after the first full run is entered in the Deviation log. Quick smoke runs may be done before the full runs and are listed in the Deviation log.

## Labels for reporting ratios

A ratio is labelled "differs from configured" in tables when it is outside 0.98 to 1.02, and "equal at this tolerance" otherwise. These labels describe the ratio only.

## Reporting rules

1. Results are reported as effective multipliers and ratios next to the configured value and next to the paper reading, with the assumptions of item 10 of the Quantities section repeated beside each composed result.
2. The text does not report epsilon or delta and does not characterise the framework's behaviour as a defect. The words that the release gate bans are not used.
3. Where the measurement differs from the paper reading the text says what configuration would give the paper reading, or says that none was found.
4. Only the listed versions were run. Nothing is claimed for other releases.
5. Anything not confirmed is labelled unconfirmed, including the reason for the factor 2 in the paper.
6. Failed predictions stay in the record.
