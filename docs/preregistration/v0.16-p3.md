# v0.16 P3 pre-registration: breaching as the primary inversion attack on CIFAR-10

Status: written before any P3 experiment code was run. Date: 2026-11-24. The commit that adds this file is the timestamp.
Script: `scripts/p3_breaching_cifar10.py` (written after this file). Runbook: `docs/v0.16-p3-colab-runbook.md`.

## Question

In v0.15 check B1 the repository's own gradient inversion attack lost to the `breaching` library on a matched setup (ratio 1.86 against the tuned configuration, FAIL). The aggregate-at-floor claims of v0.14 and v0.15 therefore rested on the weaker attack. P3 answers three questions on a harder dataset and a CNN.

1. With `breaching` as the primary attack, does the plaintext view stay clearly above the label-only floor?
2. With `breaching` as the primary attack, does the SecAgg+ aggregate view stay at or below the floor?
3. With `breaching` as the primary attack, does n-1 collusion stay above the floor, and how much does SecAgg+ quantisation cost the attacker?

It is a measurement of one library release, one small CNN, one local step and the settings below. A result for the aggregate view is evidence about the attacks that were run. It is not a privacy guarantee.

## What was already known before this file was written

Stated so that predictions are not presented as blind.

1. B1 (docs/v0.15-external-baselines.md) is a FAIL on 8x8 digits with an MLP. The repo attack was untuned there and breaching was tuned. P3 gives both attacks the same tuning effort.
2. The v0.15 Fashion-MNIST CNN study (X1) showed plaintext 86%, collusion 68%, floor 58%, aggregate 45% recognisable. Its collusion row failed its rule by 0.6 points and depended on the SecAgg+ `max_weight`.
3. The label-only floor on real CIFAR-10 was computed for the 20 evaluation seeds before this file was written, because the metric and margin choices below depend on its scale. No attack was run on real CIFAR-10. Floor numbers: mean MSE 0.058, mean PSNR 13.07 dB, share of victim images with MSE below 0.05 equal to 0.50, standard deviation of the per-seed mean PSNR 1.0 dB, standard deviation over images 2.46 dB. Because half of the floor images already pass the v0.14 "recognisable" cut of 0.05, that cut separates attack from floor poorly on CIFAR-10. It is reported for continuity only and carries no pass rule. The pass rules use PSNR gain over the floor.
4. A feasibility check on a synthetic stand-in dataset on CPU follows this commit. It tests that the code runs. It informs no parameter in this file.
5. Third-party status of breaching, recorded before any run:
   * `breaching` 0.1.2 is the only release on PyPI (`pip index versions breaching`). The wheel SHA-256 is a838348beb9981bc680ff6d922d38e854a7e7fabe7afd1409befb4da5dbc06e9, the same wheel that v0.15 used. Declared dependencies: torch (>=1.10), torchvision, hydra-core (>=1.1), scipy, lpips. Licence MIT.

## Setup (fixed)

| Item | Value |
|---|---|
| Data | CIFAR-10 train split, 50,000 images, 3x32x32, pixels divided by 255, range [0, 1]. Real data only. A synthetic stand-in exists in the script for the CPU smoke test and is refused outside `--quick`. Every JSON names its data source and the stand-in flag |
| Model | Small CNN: conv 3 to 16 (3x3, pad 1), ReLU, max pool 2, conv 16 to 32 (3x3, pad 1), ReLU, max pool 2, linear 2048 to 10. 25,594 parameters. No batch norm and no dropout. Inputs are used unnormalised in [0, 1] |
| Global model | One checkpoint shared by all seeds. Trained on the first 20,000 entries of the permutation `default_rng(12345).permutation(50000)`. Adam, learning rate 1e-3, batch 128, 10 epochs, torch seed 0. The checkpoint SHA-256 and a held-out accuracy are written to every JSON. Sharing one model across seeds means model to model variance is not in the intervals. This is listed as a limitation |
| Client records | For seed s, the permutation `default_rng(1000 + s).permutation(...)` of the 30,000 images outside the training subset. The first 32 entries are the client records, 8 per client in order. Client 0 is the victim |
| Public pool (for the floor) | All 50,000 images except the 32 client records |
| Clients and batch | N = 4 clients, B = 8 records each, one full-batch SGD step at learning rate 0.15, cross entropy with mean reduction. Only N = 4 is run in P3 |
| Attacker knowledge | Initial model, learning rate, labels of the attacked records. For the aggregate view the labels of all 32 records (joint oracle, a favourable privilege, as in v0.14 and v0.15). The attacker never sees pixels |
| Scoring | Per-image MSE, PSNR (10 log10 of 1 / MSE, data range 1) and SSIM (Gaussian window 11, sigma 1.5, K1 0.01, K2 0.03, mean over channels). Optimal one to one matching of reconstructions to originals by MSE is applied (evaluator privilege, as `score_victim`). The victim rows are reported. For the aggregate view the matching covers all 32 images and the 8 victim rows are reported |

### Views (definitions kept from v0.14 and v0.15)

| View | Definition |
|---|---|
| plaintext | The victim's individual model delta. The gradient handed to every attack is delta divided by the learning rate |
| aggregate | Weighted mean of the four updated weight vectors after the upstream Flower SecAgg+ quantiser arithmetic (clipping range 8, quantisation range 2^22, stochastic rounding seeded by the seed, `max_weight` 1000, equal weights). The model delta is the initial model minus this aggregate, stored as float32 parameters. The quantiser is a numpy copy of `flwr.common.secure_aggregation.quantization` and a unit test compares it with the installed Flower where available |
| collusion | The server plus clients 1 to 3 subtract their own weighted updates from the aggregate and rescale by total weight over victim weight (`collusion_view` of `scaling_study.py`). The result is the victim's update up to quantisation error |
| label-only floor | Every victim record rebuilt as the class-average image of the public pool, using the true label. No matching (the floor attacker needs none). The same floor is attached to every row, together with the matched floor and the mean-image floor for context |

### Attacks

Primary, `breaching` 0.1.2. The library class is called directly (`breaching.attacks.prepare_attack`) with the shipped `invertinggradients` configuration (cosine similarity objective, Adam, signed gradients, step size 0.1, step decay, box constraint, random normal initialisation, one restart), with two overrides only: `optim.max_iterations=4000` and the total variation scale chosen by the tuning rule below. Labels are passed in, so the library's label recovery is not used. Data mean 0 and std 1 (identity), so the box is [0, 1]. The iteration count is 4,000 and not the shipped 24,000 for compute reasons. It matches the tuned configuration of v0.15 B1. The shipped 24,000 iteration configuration is run as a secondary row (below) to show what the reduction costs.

Secondary, the repository's own attack, ported unchanged in form to 3x32x32 inside the script: Adam on the dummy images, learning rate 0.1, 3,000 iterations (the Fashion-MNIST CNN setting of v0.15), squared L2 gradient matching, initial images uniform in [0.2, 0.8] with generator seed s + 1, clamp to [0, 1], total variation as the mean absolute difference along both spatial axes with weight chosen by the tuning rule.

### Tuning rule (the only tuning)

Tuning seeds are 9000, 9001 and 9002 (24 victim images per view). Evaluation seeds are 0 to 19. No evaluation seed is used for any choice.

| Attack | Grid | Fixed |
|---|---|---|
| breaching | total variation scale in {0.2, 0.05, 0.01, 0.001} | 4,000 iterations, everything else shipped |
| repo | total variation weight in {0.0005, 0.05, 0.1, 0.5} | 3,000 iterations, step 0.1 |

Each attack is tuned separately for the plaintext, collusion (`max_weight` 1000) and aggregate views. The criterion is the highest mean PSNR over the tuning images. Ties go to the earlier grid entry. The grid and the criterion are fixed here. Both attacks get four candidates per view on the same seeds, which equalises the search effort that B1 left uneven. The control row K0 uses the plaintext winner. The `max_weight` 16 collusion row uses the collusion winner. The exact aggregate row uses the aggregate winner. An attacker could do this tuning on simulated clients with public data, so it does not assume access to victim data. All tuning results are saved and reported.

## Hypotheses and predictions

Gain means the paired difference in PSNR (dB) between the attack reconstruction and the floor reconstruction of the same victim image, averaged over the 8 victim images of a seed. The unit of analysis is the seed. The interval is a 95% percentile bootstrap over the 20 evaluation seeds, 10,000 resamples, bootstrap seed 0. A pass rule that uses the lower limit is read at that limit and never at the point estimate.

| ID | View and attack | Prediction | Pass rule | Confidence |
|---|---|---|---|---|
| K0 | Control: plaintext, batch of 1 (the first 4 victim records attacked one at a time), breaching | The harness and the configuration work when the problem is easy | Lower limit of gain at least +2.0 dB | 0.8 |
| R1 | Plaintext, B = 8, breaching | Clearly above the floor | Lower limit of gain above +1.0 dB | 0.6 |
| R2 | Aggregate, `max_weight` 1000, breaching | At or below the floor | Upper limit of gain at most +1.0 dB. Labelled vacuous if the upper limit is below -1.0 dB | 0.8 |
| R3 | Collusion n-1, `max_weight` 1000, breaching | Above the floor, below plaintext | Lower limit of gain above +1.0 dB | 0.4 |
| R1r, R2r, R3r | The same three views, repo attack | Same rules as R1, R2 and R3 respectively | As R1, R2 and R3 | 0.5, 0.9, 0.3 |
| B1c | B1 analogue on plaintext, B = 8 | The repo attack is not much weaker than breaching | Mean MSE of the repo attack at most 1.5 times the mean MSE of breaching (point ratio, as in B1, interval reported) | 0.4 |
| O1 | Ordering | Quantisation costs the attacker | Gain(plaintext) minus gain(collusion), paired over seeds, has a lower limit above 0, breaching | 0.6 |
| O2 | Ordering | Collusion beats the aggregate | Gain(collusion) minus gain(aggregate), paired over seeds, has a lower limit above 0, breaching | 0.8 |

Reasoning behind the less obvious entries. Class-average images are a strong prior in PSNR on natural images (floor PSNR 13 dB), and gradient matching adds high frequency error, so even plaintext B = 8 may fail to beat it by 1 dB (R1 at 0.6). The SecAgg+ error on the victim's weights is about 4 x 1.2e-4 = 5e-4 per coordinate at `max_weight` 1000 against a delta of order 3e-3, which is enough to damage the match (R3 at 0.4, O1 at 0.6). R2 is expected to pass and to be vacuous, as S1 was in v0.15.

If K0 fails, rows R1 to R3 are still reported but are labelled "not interpretable as attack strength evidence", because the harness or configuration is then suspect. A cause is sought before any claim is made.

### Rows reported without a pass rule

Collusion at `max_weight` 16 (breaching and repo). Aggregate computed from the exact unquantised four-client mean (breaching, labelled "aggregate_exact", it separates what quantisation does from what batch mixing does). Plaintext with the shipped 24,000 iteration, total variation 0.2 breaching configuration ("ig_library_default", plaintext only). SSIM gain with the same interval for every row. The share of victim images where the attack MSE is below the floor MSE for the same image. The share of images with MSE below 0.05 (Wilson interval, pooled over images, noted as optimistic because images of a seed are not independent). The breaching minus repo paired gain difference for each view. Wall time per row. If PSNR and SSIM gains disagree in sign for a row, the disagreement is stated in the verdict text.

## Seeds, sizes, detection power

20 evaluation seeds (0 to 19), 8 victim images per seed per view, 160 images per row (80 for K0). 3 tuning seeds. The verdicts are computed only when all 20 seeds are present. With fewer seeds the summary is labelled "not the pre-registered size, no verdict".

Power, under the assumption that the seed-level standard deviation of gain is 1.5 dB (an assumption. The floor PSNR itself has a seed-level standard deviation of 1.0 dB) and a t-based approximation of the bootstrap interval, whose half width at 20 seeds is 0.70 dB.

| True mean gain (dB) | P(R1 or R3 rule passes, margin +1.0) | P(R2 rule passes, margin +1.0) | P(K0 rule passes, margin +2.0) |
|---|---|---|---|
| 0 | 0.00 | 0.81 | 0.00 |
| 1 | 0.02 | 0.02 | 0.00 |
| 2 | 0.81 | 0.00 | 0.02 |
| 3 | 1.00 | 0.00 | 0.81 |
| 4 | 1.00 | 0.00 | 1.00 |

So a true gain of +2 dB or more is detected for the plaintext and collusion rows, and a true gain of +1 dB or more is rejected by R2 with probability at least 0.98. A true gain of 0 dB passes R2 only 81% of the time, so a failed R2 with a point estimate near zero is a power limit and is reported that way. If the observed seed-level standard deviation is above 3 dB the half width exceeds 1.4 dB, these power statements are void and the report says so. The smallest gain the design separates reliably from zero is about 1.5 dB.

## Reporting rules

1. Every row is reported as measured, next to the floor, with the interval. No row is dropped. A failed prediction is written as FAIL and not reworded.
2. A FAIL where the point estimate is on the passing side but the interval is not is labelled "FAIL, underpowered". A FAIL with the point estimate on the failing side is labelled "FAIL".
3. Thresholds and grids are never changed after the first run that uses them. If one turns out to be badly chosen, the original stays, a dated entry is added to the deviation log, and both outcomes are reported.
4. A reconstruction that is non-finite or an all zero return of the library is scored as returned and counted in an `invalid_reconstructions` field. It is not replaced or retried.
5. The text does not describe the aggregate result as privacy. It states what the attacks achieved. Statements that the aggregate sits at or below the floor are conditional on these attacks, this model and this setup.
6. Results come from real CIFAR-10 on the Colab GPU run. CPU smoke output and any run on stand-in data never appear as results.
7. GPU runs are not bitwise reproducible. The JSON records the device, torch and CUDA versions, so a rerun can differ in the last digits.
8. Findings about third-party software are reported privately to the maintainers before any public description.

## Limitations stated in advance

One dataset, one small CNN, one shared global model, one local step on 8 records per client, known labels, known initial model and learning rate, 4 clients. No multi-step updates, no larger batches, no analytic or malicious server attacks. The aggregate attacker is a joint oracle with the labels of all 32 records. The 4,000 iteration breaching configuration is shorter than the library default. Only four total variation values were tried per view. SecAgg+ is simulated with the upstream quantiser arithmetic and not run over a real network. PSNR rewards smooth images and the class average is smooth, so a gain near zero does not mean nothing leaked.

## Deviation log

Added after the runs. Nothing above this heading was edited.

1. Parameter count. The setup table says 25,594 parameters. The architecture as written has 448 + 4,640 + 20,490 = 25,578 parameters. The script and its test use 25,578. The architecture itself is unchanged. Dated 2026-11-24, before any evaluation run.
2. Pipeline probes before the evaluation. After this file was committed and before any tuning or evaluation run, a harness check ran on real CIFAR-10 with the trained model on seed 9900 (outside both the tuning range 9000 to 9002 and the evaluation range 0 to 19). It attacked four single records with breaching at 1,500 iterations and total variation 0.05, to confirm that the objective falls and the gradient cosine of the reconstruction approaches 1 (0.975 to 0.995 observed, reconstructions above the floor PSNR for 3 of 4 records). A timing run on the same seed measured seconds per iteration. It also confirmed that SecAgg+ quantisation at `max_weight` 1000 changes the victim gradient by 4.6% (relative L2) and at 16 by 0.07%, and the aggregate by 2.0%. No parameter, grid, margin or rule in this file was changed after these probes. The 1,500 iteration and total variation 0.05 values were arbitrary probe choices and are not tuning results.
3. Implementation choices the file left open. Attack generator seeds are seed + 1 for the batch rows and seed + 1 + 100 (k + 1) for single-record control attack k. The control attacks use the plaintext total variation winner and 4,000 iterations. The matched floor and mean image floor are stored next to the headline floor and carry no rule. A reconstruction with non-finite values is stored with non-finite entries replaced by zero and is counted in `invalid_reconstructions`. An all-zero return of the library is counted the same way.
