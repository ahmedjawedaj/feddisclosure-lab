# v0.16 P2 pre-registration: audit of FedML's differential privacy mechanisms

Status: written before any FedML mechanism was executed. Date: 2026-11-24.
Subject: `fedml` 0.9.6 (PyPI release of 2025-02-24, wheel sha256 `59879651907d05b635f0a6294a1cb87446a7c588c175c436802b241490136c68`).
Method: the same as `docs/preregistration/v0.16-p1.md` (Flower). Harness math is copied from `scripts/audit_flower_dp.py`.

## Question

For each differential privacy mechanism that FedML 0.9.6 ships in `fedml/core/dp`, does the privacy level a user would compute from the configured parameters match the privacy level of the mechanism that actually runs?

This is a measurement of one framework version under stated configurations. It is not a claim about how FedML is intended to be used. The wheel ships no documentation text for the DP parameters (no markdown, yaml or notebook mentions `sensitivity`, `epsilon`, `mechanism_type`, `max_grad_norm` or `rdp`), so "claimed" below always means what the configured parameters imply under the stated textbook reading, taken from the class docstrings and the referenced papers. Each row defines its reading.

## What was already known before this file was written

Stated so that predictions are not presented as blind.

1. All files under `fedml/core/dp` and the two call sites (`core/alg_frame/server_aggregator.py` and `core/alg_frame/client_trainer.py`) were read in full before writing predictions. All predictions come from code reading, partly in an earlier private session and re-read in this one.
2. The following were computed analytically with scratch code that imports no FedML class: the exact Gaussian delta and epsilon for the classical calibration grid below, the exact Laplace privacy profile (checked against direct numerical integration, for example shift 4 and epsilon 1 gives 0.77687 both ways), the epsilon that the RDP to (epsilon, delta) conversion gives for a single full-participation Gaussian step, and the expected Clopper-Pearson bounds for the rows with power. Rows G1, LP1 and RA2 are therefore partly confirmatory.
3. The `fedml/core/dp` tree is byte-identical in every release checked (see Prior art).
4. No FedML mechanism was executed before this file was committed. The package was installed into an isolated environment and its files hashed. Nothing in it was imported.

## Environment and method

Environment. A virtual environment at `/tmp/fedml_venv` created with `--system-site-packages` so that the already installed numpy 2.5.3, scipy 1.18.1 and torch 2.15.0 (CPU) are reused and nothing is downloaded for them. `fedml==0.9.6` was installed into the environment only, with `--no-deps`. The installed DP tree hashes identically to the extracted wheel used for reading. FedML declares `numpy<2`, which this environment does not satisfy and the DP modules do not need.

Isolation. The harness never runs `fedml/__init__.py`, which starts MLOps, tracking and telemetry code. It registers bare module objects for `fedml`, `fedml.core` and `fedml.core.common` in `sys.modules`, with `__path__` pointing at the installed directories, and then imports `fedml.core.dp.*` and `fedml.core.common.ml_engine_backend`. Those are the only FedML files loaded. During mechanism runs the harness replaces `socket.socket` with a function that raises, so a network call would fail loudly.

Method per row, as in P1.
1. Noise-free sensitivity from the shipped class where the class has a clipping step, otherwise from the crafted input difference.
2. Noise scale. Gaussian and Laplace noise is drawn as one batched call of the shipped mechanism on a tensor of shape (20,000, 16), which gives 20,000 independent rows because the noise is element-wise independent by construction. The harness checks column correlations and lag-1 correlation. Stateful classes (`DP_Clip`) are called one tensor at a time because the call order is the subject.
3. Effective Gaussian parameter mu = sensitivity / sigma and exact (epsilon, delta) from Balle and Wang (2018). For Laplace the exact profile delta(eps) = 1 - exp((eps - eps_pure) / 2) for eps below eps_pure, where eps_pure = L1 sensitivity / scale.
4. Empirical lower bound where there is power: a threshold test with 200,000 trials per world and 95% Clopper-Pearson bounds at delta 1e-5. Gaussian rows use the projection onto the difference direction and a threshold fixed from the predicted mu with `planned_threshold`. Laplace rows use the likelihood-ratio statistic of the predicted Laplace law and a threshold fixed from a simulated predicted distribution (numpy, seed 7, 400,000 draws per world) before the final trials.

Adjacency. Central rows use zero-out (the target's update replaced by zero, result count unchanged). Local rows use replace-one between an update and its negation. Replace-one is the secondary column for central rows. Configuration: 16 float32 parameters, delta 1e-5 unless stated, seeds fixed in the script.

## Rows and predictions

Predictions marked P were written from code reading before any execution. Rows marked "candidate" are the candidates from the earlier private reading.

### Gaussian mechanism (`mechanisms/gaussian.py`, through `DPMechanism("gaussian", ...)`)

Claimed: the output is (epsilon, delta)-DP for a query of L2 sensitivity `sensitivity`, by the classical calibration sigma = sqrt(2 ln(1.25/delta)) * sensitivity / epsilon, which is proved for epsilon at most 1.

| Row | Configuration | Prediction |
|---|---|---|
| G1 | epsilon in {0.1, 0.5, 1.0}, delta in {1e-5, 0.1}, sensitivity 1. delta 0.1 with epsilon 0.1 is the configuration used in the package's own test file | P: measured sigma equals the formula within 1%. Exact delta is below the configured delta in all six cells, ratio 0.00026, 0.0016 and 0.0041 for delta 1e-5 and 0.0020, 0.012 and 0.031 for delta 0.1. Exact epsilon at 1e-5 is 0.061, 0.353, 0.751. The mechanism meets its claim, conservatively. |
| G2 (candidate) | epsilon in {1.0, 1.0000001, 2, 5, 10} | P: epsilon 1.0 is accepted and every larger value raises `ValueError`. The code refuses the range where the classical calibration is not proved, which is a difference from the Flower local DP rows. |

### Laplace mechanism (`mechanisms/laplace.py`, through `DPMechanism("laplace", ...)`)

Claimed: (epsilon, delta)-DP for a query of L1 sensitivity `sensitivity`, scale = sensitivity / (epsilon - ln(1 - delta)).

| Row | Configuration | Prediction |
|---|---|---|
| LP1 | delta in {0, 1e-5, 0.1, 0.5}, epsilon in {0.1, 1, 5}, sensitivity 1 | P: measured scale equals the formula within 1%. The scale is below sensitivity/epsilon whenever delta is above 0, so the pure epsilon of the executed Laplace is epsilon - ln(1 - delta), for example 1.00001 for epsilon 1 and delta 1e-5. The exact delta at the configured epsilon is 1 - sqrt(1 - delta), about delta/2, so the (epsilon, delta) claim is met in every cell. |
| LP2 | zero-out update of L2 norm 1 with `sensitivity` set to 1, epsilon 1, delta 1e-5. Concentrated update (all mass on one coordinate, L1 norm 1) and spread update (equal mass on 16 coordinates, L1 norm 4) | P: the same `sensitivity` argument is an L2 bound for the Gaussian class and must be an L1 bound for the Laplace class. Concentrated update: eps_pure 1.00001, matches. Spread update: eps_pure 4.00004, which is sqrt(d) times the configured epsilon for d = 16. Reported as a configuration note, not as a property of the mechanism, because the mechanism is correct for its stated L1 reading. |
| LP3 | output dtype of `add_noise` on float32 input, and on an int64 buffer, for both mechanisms | P: Laplace returns float64 (noise is a numpy float64 tensor) and Gaussian returns float32. An int64 buffer comes back as a floating tensor in both. Not a privacy measurement, recorded as an observation. |

### Clipping and Gaussian noise frame (`frames/dp_clip.py`, `DP_Clip`)

Claimed: the docstring cites McMahan et al. (ICLR 2018). Clip each user update to L2 norm C, add Gaussian noise with standard deviation z * C / (q * W) to the average estimator. Reading used: Gaussian mechanism with multiplier z, mu = 1/z per release, with q * W given by `qw`.

| Row | Configuration | Prediction |
|---|---|---|
| K1 | `clip_local_update` on updates of norm 0.5, 1, 5, 50 with C = 1 | P: norm after clipping is at most C, equal to C within 1e-5 relative for norms above C, unchanged below C. The input tensors are modified in place. `add_local_noise` adds no noise, it subtracts the global parameters and clips. |
| K2 (candidate) | `compute_noise` called repeatedly on a fresh instance, C = 1, z = 1, `qw` = 100 (1,000 training samples, 10 of 100 clients per round) | P: `compute_noise` divides `self._scale` by `qw` on every call, so the call k has sigma = z * C / qw^k. Expected sigma 1e-2, 1e-4, 1e-6 and so on. The noise is exactly zero in float32 from about call 22 on. Within one `add_noise` the first tensor gets zC/qw, the second zC/qw^2, and the state carries over to the next round. |
| K3 (candidate) | `add_global_noise` on a two-tensor model with the same configuration | P: returns `None`. The input dict is modified in place and holds the original values divided by `qw` with no noise added. The noised dict is built and discarded. |
| K4 | `FedMLDifferentialPrivacy.init` with `dp_solution_type` "dp_clip", then the four predicates the aggregator and trainer use | P: `is_local_dp_enabled` and `is_global_dp_enabled` are both false for "dp_clip", so neither `client_trainer.py` nor `server_aggregator.py` calls `DP_Clip` in 0.9.6. The class is reachable only by direct calls. |

## Detection power

- Sigma and scale. 20,000 rows of 16 values give a relative standard error of about 0.13% for a Gaussian sigma and about 0.18% for a Laplace scale. Any scale deviation above 1% is detected. The 2% rule below is therefore not a power limit.
- Exact values (K2, CD2, RA1, LP3, G2) are deterministic outcomes, detection power is not a question.
- Clopper-Pearson bounds with 200,000 trials per world can certify epsilon up to about 10.9 at delta 1e-5. Expected certified bound if the prediction holds: LD1 a = 5 about 1.2, a = 25 about 10.6, LP2 spread update about 2.9 (against exact 4.00). They have no power for G1 and LD1 a = 1 (mu 0.2), for LP1, and for LP2 concentrated. For those rows the claim rests on measured scale plus the exact formula, which is the same limit as P1 row L1.
- RA2, RA3 are exact comparisons with a reference computed independently of FedML.

## What would count against the predictions

A row is reported as "matches the claim" if the measured Gaussian parameter, or for Laplace the measured pure epsilon, is within 2% of the claimed one. Any predicted mismatch that measures within 2% is reported as a failed prediction. A predicted exception that does not occur, or a different exception type, is reported as a failed prediction. No row is dropped. The candidate list from the earlier private reading is scored one by one in the results.

## Reporting rules

Results are reported as measured values next to configured values, with exact epsilon and delta. The text does not characterise FedML's behaviour as a defect. Each mismatch row states the configuration needed to reach it and whether the framework logs or raises anything. Rows reached only by direct calls (K1 to K3, RA rows) say so. Findings stay in this repository tree. Nothing is sent to FedML or published outside it.
