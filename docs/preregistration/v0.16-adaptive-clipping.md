# v0.16 T8b pre-registration: how Flower implements adaptive clipping

Status: written before the harness exists and before any measurement of this phase. Date: 2026-11-25.
Subject: the four adaptive clipping strategy classes in `flwr` 1.27.0 (the version pinned by this repository) and in `flwr` 1.44.0.
Reference: Andrew, Thakkar, McMahan and Ramaswamy, "Differentially Private Learning with Adaptive Clipping", arXiv 1905.03871.

## Question

Does the adaptive clipping that Flower runs follow the relations and update rule of Andrew et al. (2021), when each relation is checked from the configured parameters and from the observable output of the public strategy classes?

This is a measurement of two framework versions under stated configurations. It is not a claim about how Flower is meant to be used. "Paper reading" below always means the relation as written in the paper, with the source named in the next section.

## The paper relations used

Source read once through a summarising fetch of the ar5iv copy of the paper, with the formulas cross-checked against an earlier read in `t8_adaptive_clipping.md`. The ordering of steps in a round was read from the pseudocode of Algorithm 1 in that single fetch, so the ordering reading is moderately confirmed and not double checked.

Round t, m sampled users, clip C_t.

1. Bit. b_i = 1 if the L2 norm of user i's update is at most C_t, so b_i = 1 means the update was NOT clipped.
2. Noisy fraction. b_tilde = (1/m) * (sum of b_i + N(0, sigma_b^2)). The noise has standard deviation sigma_b on the count, so the noise on the fraction is sigma_b / m.
3. Geometric update. C_(t+1) = C_t * exp(-eta_C * (b_tilde - gamma)). Defaults in the paper: gamma 0.5, eta_C 0.2, C_0 0.1, sigma_b = m / 20. If b_tilde is above gamma, the clip shrinks.
4. Budget split. z_delta = (z^-2 - (2 sigma_b)^-2)^(-1/2), equivalently z = (z_delta^-2 + (2 sigma_b)^-2)^(-1/2). Here z is the effective total noise multiplier and z_delta the one applied to the sum of clipped updates. It needs z < 2 sigma_b.
5. Order in a round (Algorithm 1). Users clip with C_t, the Gaussian noise on the sum has standard deviation z_delta * C_t, the model is updated, and only then C_(t+1) is computed. So the noise uses the OLD clip norm.
6. Cohort size. The paper uses a fixed m. It says nothing about fewer users replying, so row A7 has no paper reading.

## What was already known before this file was written

Stated so that predictions are not presented as blind.

1. The source of all four classes was read in both versions before writing predictions. All predictions below come from code reading. The legacy classes are identical between the two versions apart from import paths. The Message API classes differ only in how arrays are wrapped.
2. The helper `compute_adaptive_noise_params` was called locally in 1.27.0 for three inputs before this file was written (see `t8_adaptive_clipping.md`). Row A1 is therefore confirmatory for 1.27.0 on those inputs and predictive for 1.44.0.
3. Row A3, scenario "all updates clipped" on V1, is confirmatory. The earlier phase (`docs/v0.16-p1-flower-dp-audit.md`, rows A1 and A2) measured that the clip norm shrinks to 0.905 of its value in a round where all 10 updates are clipped. No other row has been run.
4. The code reading found that the bit passed to the clip update is set when an update IS clipped. That is the opposite of the paper's b_i. The older compatibility client in `flwr` sets its bit to "not clipped". Rows A3, A4, A10 and A11 are written around this reading.
5. The earlier results document says the client-side adaptive variant adds noise before it updates the norm. The code reading for this phase says both client-side variants update the norm first and then add noise. Row A6 tests this.

## Method

All rows run the real Flower classes in process. The inner strategy is `FedAvg` with equal `num_examples` of 1, fed fake `FitRes` objects (legacy API) or `Message` objects (Message API) built from a 16 parameter float32 model whose global value is zero. A client update is a vector along the first axis with a chosen L2 norm.

1. Noise free path. Constructing a strategy with noise multiplier 0 gives `clipped_count_stddev` 0 and a model noise multiplier of 0 (row A1e). Rows that need exact clip arithmetic use this path, so no monkeypatching is needed.
2. Reading the counted fraction. After one round from a known clip C_0, the fraction the strategy counted is recovered from the new clip as f = gamma - ln(C_1 / C_0) / eta_C, with gamma 0.5 and eta_C 0.2 unless stated. This uses only the public attribute `clipping_norm`.
3. Client-side variants V2 and V4. In rows A3, A4 and A4b the bit comes from the real client mod (`flwr.client.mod.adaptiveclipping_mod` for V2 and `flwr.clientapp.mod.adaptiveclipping_mod` for V4), fed the clip norm that the strategy puts in its config. In the noise rows (A5 to A8, A10, A11 where a bit count is the input) the fake client replies carry a chosen number of set bits directly.
4. Noise scale. Model noise is the output minus the output of a noise free twin strategy at the same clip, per coordinate. The scale is the root mean square over coordinates and runs.
5. Randomness. Where a row draws noise, `np.random.seed` is set to a fixed value in the harness, so reruns reproduce. Row A8 tests what that does.
6. Each row records `script_sha256`, the Flower version, the variant and the measured values next to the configured values.

## Rows and predictions

"Paper" is the reading of the relations above. "Prediction" is for Flower. A row is called held when every measured value is inside its stated tolerance of the prediction. Agreement with the paper is recorded in its own column and does not decide whether the prediction held. Unless a row says otherwise the same prediction applies to V1 to V4 and to both versions. Rows A1 to A8 are run on all four variants. Row A9 is the client-side statement.

### A0 Defaults

Configuration: construct each class with only `strategy`, noise multiplier 1.0 and `num_sampled_clients` 100, and read the signature defaults.

| Quantity | Paper | Prediction |
|---|---|---|
| `initial_clipping_norm` | 0.1 | 0.1 |
| `target_clipped_quantile` | 0.5 | 0.5 |

### A1 Noise multiplier adjustment

| Case | Input | Paper | Prediction | Tolerance |
|---|---|---|---|---|
| A1a | `clipped_count_stddev` None | sigma_b 5.0 and z_delta 1.005038 | stddev 5.0 and multiplier 1.005037815259212 | 1e-9 absolute |
| A1b | `clipped_count_stddev` 10.0 | z_delta 1.001252 | stddev 10.0 and multiplier 1.0012523486435176 | 1e-9 absolute |
| A1c | z = 1, `clipped_count_stddev` 0.5 | invalid, needs z < 2 sigma_b | `ValueError` | exception type |
| A1c2 | z = 10 with default sigma_b 5.0, so z = 2 sigma_b | invalid, the bound is strict | `ValueError` | exception type |
| A1c3 | z = 9.99 with default sigma_b 5.0 | valid | no error and multiplier equal to (9.99^-2 - 10^-2)^(-1/2) | 1e-9 relative |
| A1d | grid of 12 valid inputs, z in 0.1, 0.5, 1, 2, 5 and sigma_b chosen with z < 2 sigma_b | z_delta at least z | stored multiplier at least z in every case | strict inequality or equality |
| A1e | z = 0, then z = 0 with `clipped_count_stddev` 3.0, then z = 1 with `clipped_count_stddev` 0.0 | not specified | (0.0 stddev and 0.0 multiplier), then (3.0 and 0.0), then `ValueError` | exact |

Configuration needed for a count with no noise while z is positive: none, since the third case of A1e raises. A noise free count is reached only with z = 0.

### A2 Effective total privacy

Configuration: for each of (z 1.0, m 100, sigma_b None), (1.0, 100, 10), (0.5, 10, None) and (0.3, 200, 2), build the strategy, read the stored multiplier z_delta and stored `clipped_count_stddev` sigma_b, then compute z' = (z_delta^-2 + (2 sigma_b)^-2)^(-1/2).

Paper: z' = z. Prediction: z' equals the configured z. Tolerance: 1e-9 absolute.

### A3 Geometric clip update

Configuration: z = 0, m = n = 100, C_0 = 0.1, defaults for the rest. Scenario u is the exact fraction of updates at or below the clip: 0, 0.5 or 1, built with update norms of 0.5 C_0 (inside) and 2 C_0 (clipped).

| u | Paper next clip | Prediction next clip |
|---|---|---|
| 0 | 0.11051709180756478 | 0.09048374180359596 |
| 0.5 | 0.1 | 0.1 |
| 1 | 0.09048374180359596 | 0.11051709180756478 |

The prediction is the paper rule applied to the fraction of CLIPPED updates, which follows from the code reading in item 4 above. A linear rule would give 0.2 or 0.0 at the ends, so these three values also tell the geometric form from the linear one. Tolerance: 1e-9 relative.

### A4 Bit direction

| Quantity | Paper | Prediction |
|---|---|---|
| counted fraction f | 0.70 (b = 1 for unclipped) | 0.30 (bit set for clipped) |

A4b boundary. Configuration: z = 0, n = 1, C_0 = 1.0, one update with norm exactly 1.0. Paper: b = 1 because the norm is at most the clip. ### A5 Count noise

Configuration: z = 1, m = n = 100, C_0 = 0.1, 70 updates inside and 30 clipped, clip reset to C_0 before each round, 10,000 rounds, `np.random.seed` fixed. Cases: `clipped_count_stddev` None (5.0) and 10.0. The fraction is recovered as in the method.

| Case | Paper std of fraction | Prediction std of fraction | Prediction mean of fraction |
|---|---|---|---|
| sigma_b 5.0 | 0.05 | 0.05 | 0.30 |
| sigma_b 10.0 | 0.10 | 0.10 | 0.30 |

Tolerance: standard deviation within 3 percent of the prediction, mean within 4 standard errors. A result near sigma_b itself (5 or 10) would mean the noise is added after the division.

### A6 Order of operations

Configuration: z = 0.5, n = 10, `clip_norm_lr` 1.0, C_0 = 1.0, all 10 updates clipped, default sigma_b 0.5 so z_delta = 0.5773502691896257, 20,000 rounds. Per round record the clip before (C_old) and after (C_new) the update and standardise the model noise of that round by z_delta * C / n once with each.

| Quantity | Paper | Prediction |
|---|---|---|
| standard deviation of noise standardised by C_old | 1.00 | about 0.61, outside 0.9 to 1.1 |
| standard deviation of noise standardised by C_new | about 1.65 (not 1) | 1.00 within 0.02 |

The paper uses C_t for the noise, so the paper reading is the C_old line. The prediction is that Flower uses the NEW clip, in both server-side and client-side variants. The prediction therefore differs from the paper reading. Whether the paper's ordering is the intended one for the framework was not checked beyond Algorithm 1.

### A7 Cohort size when fewer clients reply

Configuration: n = 10 configured, 5 replies (3 clipped and 2 inside with C_0 = 1.0), no failure reported.

Fraction part, z = 0, default `clip_norm_lr`. Prediction: counted fraction 0.6 (3 over `len(results)`), next clip 0.9801986733067553. Dividing by n would give 0.3 and 1.0408107741923882. Tolerance 1e-9.

Noise part, z = 0.5, 20,000 rounds, noise standardised by z_delta * C_new / n. Prediction: standard deviation 1.00 within 0.02, so the scale uses `num_sampled_clients`. Using the reply count would give 2.0.

Warning part. Prediction: Flower logs a warning that the number of replies differs from the number of sampled clients, and still aggregates. Paper: no reading, the paper fixes m.

### A8 Count noise random source

Configuration: z = 1, n = 10, 10 updates, fixed C_0. Run one round after `np.random.seed(123)`, rerun after the same seed, and run after seed 124. Also inspect each constructor signature and the global generator state.

Prediction: the constructor has no seed or generator parameter. The same seed gives bit-identical clip and aggregate on both runs. A different seed gives a different clip and aggregate. The global numpy state advances during a round. So the count noise and the model noise both come from the numpy global generator and are not seeded by the strategy. Tolerance: exact equality for the first, inequality for the second.

### A9 Client-side variants

The predictions of A0 to A8, A10 and A11 apply unchanged to V2 and V4 except as follows.

1. A3, A4 and A4b take the bit from the real client mod instead of the server. Prediction: the mod sets the bit when the update is clipped, so the values equal those of V1 and V3.
2. A6. Prediction: AFTER, the same as server-side. Client-side code aggregates first, then updates the clip, then adds noise. The earlier results document says the opposite. If the prediction holds, that sentence needs correcting.
3. A7. Prediction: the same, with the count taken from the `len(results)` replies that carry a bit.

### A10 Growth when every client is clipped

Configuration: z = 0, n = 100, defaults, C_0 = 0.1, every update clipped in every round, 23 rounds. Paper: C grows tenfold, 0.1 * exp(2.3) = 0.9974182454814718. Prediction: C shrinks to 0.1 * exp(-2.3) = 0.010025884372280375. Tolerance: 1e-9 relative. The per round factor stays inside [0.9048, 1.1052] at defaults, which is exp(-0.1) to exp(0.1), because the fraction is at most 0.5 away from the target 0.5. The paper's general bound is exp(eta_C) = 1.2214, reached only when the fraction is 1 away from the target.

### A11 Closed loop against a fixed norm distribution

Configuration: z = 0, n = 100, defaults, 200 rounds, update norms fixed at 100 evenly spaced values from 0.5 to 1.5 (median 1.0). Two starts: C_0 = 0.1 and C_0 = 10.

| Start | Paper after 200 rounds | Prediction after 200 rounds |
|---|---|---|
| C_0 = 0.1 | within 10 percent of 1.0 | 0.1 * exp(-20) = 2.061153622438558e-10 |
| C_0 = 10 | within 10 percent of 1.0 | 10 * exp(20) = 4851651954.097902 |

Why: with the bit set for clipped updates and the rule shrinking the clip when the fraction is above the target, a clip below every norm keeps shrinking and a clip above every norm keeps growing, so the clip moves away from the target quantile. Tolerance: 1e-9 relative. Configuration needed for the paper behaviour: none found, the target quantile argument only moves the fixed point and does not change the sign.

## Detection power

Exact arithmetic rows (A0 to A4b, A7 fraction, A10, A11) are deterministic and compared at 1e-9, so any deviation larger than float rounding is detected. A5 with 10,000 rounds has a standard error of about 0.7 percent on the standard deviation, so the 3 percent tolerance is about four standard errors and the 20 times difference between sigma_b / m and sigma_b is far outside it. A6 and A7 with 20,000 rounds over 16 coordinates have a standard error near 0.1 percent, and the predicted gap to the alternative reading is at least 39 percent.

## What would count against the predictions

A row is reported as failed if any measured value is outside its stated tolerance. No row is dropped and no tolerance is changed after a run. A prediction that fails is reported as a failed prediction with the measured value. A harness change after the first full run is entered in the Deviation log.

## Reporting rules

1. Results are reported as measured values next to configured values and next to the paper reading.
2. The text does not characterise the framework's behaviour as a defect. Words such as bug, flaw or vulnerability are not used.
3. Each row where the measurement differs from the paper reading states the configuration needed to reach the paper reading, or says that none was found.
4. Only the listed versions were run. Nothing is claimed for other releases.
5. Anything not confirmed is labelled unconfirmed, including the paper ordering reading above.

## Deviation log

Added after the runs. Nothing above this heading was edited.

1. Row A8 configuration. The pre-registration named z = 1 with n = 10. Flower rejects that at construction because z equals 2 times the default sigma_b of 0.5, which is the same boundary as row A1c2. The harness uses n = 20 with 20 updates, and 8 set bits for the client variants. This was found in the first smoke run and the harness was changed before any full run.
2. Smoke runs. Before the full runs the harness was run in quick mode on 1.27.0 and on 1.44.0 and the output was read. In quick mode A5 was outside its 3 percent tolerance, because 500 rounds give a standard error of about 3 percent. No tolerance and no round count of the full run was changed.
3. Choices the pre-registration left open. The A1d grid is z in 0.1, 0.5, 1, 2 and 5 each with sigma_b of 0.6 z and 5 z, plus (1, 0.51) and (1, 100). The A7 warning is matched by the text "sampled clients" in a WARNING record of the `flwr` logger. For the client variants the set bits are the first k replies. Noise is the output minus the output of a noise free twin strategy at the same clip.
4. Row A9 is emitted as one summary entry per client-side variant listing whether each of its rows held.
5. Command line. The 1.27.0 run used `python3 -I`. The 1.44.0 run used `PYTHONPATH=/tmp/flwr44` without `-I`, because `-I` ignores `PYTHONPATH`. Both used the same interpreter and packages.
6. One check outside the harness and not in the JSON, not pre-registered. Constructing each of the four classes with `clip_norm_lr` of -0.2 raises `ValueError` on both versions.
7. The Flower warnings were printed to the terminal during the runs. This does not affect the results.
