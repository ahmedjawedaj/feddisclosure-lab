# v0.16.5 pre-registration: does the selection step of SVTPrivacy stay inside its claimed epsilon, and could the check have shown otherwise

Status: written before the script exists and before any real call of the filter in this phase. Date: 2026-11-26.
Subject: `nvflare` 2.9.1, file `nvflare/app_common/filters/svt_privacy.py`, and the identity of the two filter files across 2.8.3, 2.9.0 and 2.9.1.
Follows: `docs/preregistration/v0.16-nvflare.md` (v0.16.4), row N6b.

## Question

Q1. For small configurations where a violation of the accountant's claim for the selection phase (`epsilon_threshold` plus `epsilon_query`) could be seen, does the 95% lower bound on the empirical epsilon of the selected set stay at or below that claim?

Q2. For every null result in this file, what is the smallest excess over the claim that the check would have found with 80% power?

Q3. Are `svt_privacy.py` and `percentile_privacy.py` byte identical in 2.8.3, 2.9.0 and 2.9.1, and does one seeded call of each return the same output in all three?

This is a measurement of one framework version under stated configurations. A pass says nothing about other inputs, other events, other neighbouring pairs or the whole 2.9.1 mechanism.

## Why the earlier check had little power

Row N6b of v0.16.4 used a claim of 20 (the ledger `epsilon_threshold` plus `epsilon_query` at `epsilon` 20) and 200,000 runs per input. With that many runs the largest 95% lower bound that any outcome can give is about 10.9, which is below 20. The check could not fail at that claim, whatever the filter did. The result it recorded (lower bound 0.87) was true and uninformative about a violation. This file replaces it with checks whose power is stated first.

## Method and statistics

Neighbouring inputs. Neither the documentation nor the code states a neighbouring definition. The reading used is the one under which the standard sparse vector analysis gives each query sensitivity gamma: two inputs are neighbours when the clipped absolute value of every coordinate differs by at most gamma. Under that reading the most adverse pair flips every coordinate, so each pair below sets the first n entries to gamma and the rest to 0 in world a, and the first n entries to 0 and the rest to gamma in world c. All vectors are float64 and named `w`. gamma is the default 1e-5.

Event. E is the statement "the set of nonzero entries of the output equals {0, ..., n-1}". A nonzero entry is one that differs from 0.0. Selected entries carry continuous noise, so a selected entry is nonzero with probability 1.

Runs. Every run calls the real `SVTPrivacy.process_dxo` once on a fresh `DXO` of kind `WEIGHT_DIFF`. Each world is run in 5 blocks of 100,000 calls, which is 500,000 calls per world and 1,000,000 per row. Each block has its own seed set with `numpy.random.seed`. The block seed is 20261126 + 10000 * r + 100 * w + b, with r the row number (S1 is 1, S2 is 2, S3 is 3), w the world (0 for a, 1 for c) and b the block (0 to 4). A fresh filter instance is made every 10,000 calls to keep the ledger short, and the sum of `acceptance_passes` is recorded per block.

Interval. For each world the count k out of N gets a Clopper-Pearson interval with 1.25% in each tail. This is the pure Python implementation from `scripts/audit_nvflare_dp.py`. It differs from v0.16.4, which used 2.5% per tail, because four comparisons share the two intervals and the family error is kept at 5%.

Lower bound. LB is the largest of four log ratios, floored at 0: ln(lo_a / hi_c), ln(lo_c / hi_a), ln((1 - hi_c) / (1 - lo_a)) and ln((1 - hi_a) / (1 - lo_c)). Here lo and hi are the interval ends. If the true epsilon of E under this pair is at most the claim, LB exceeds the claim with probability at most 5%.

Claim. The claim for a row is `epsilon_threshold` plus `epsilon_query` from the first ledger entry. This equals the `epsilon` argument. The release epsilon is not part of the claim for selection and plays no role in E.

Block agreement. A chi-square test with 4 degrees of freedom compares the 5 block counts of a world with their pooled rate. Its survival function is exp(-x/2) * (1 + x/2).

Power. For a true log ratio e with the denominator probability p_c fixed at its predicted value, p_a equals p_c * exp(e) and SE(e) is sqrt((1 - p_a) / (N * p_a) + (1 - p_c) / (N * p_c)) with N 500,000. The normal approximation of LB gives power equal to the standard normal cdf of (e - claim) / SE - z, with z 2.2414 (one tail at 1.25%). The smallest effect at 80% power is the value e that solves e = claim + (z + 0.8416) * SE(e). This is the smallest event level epsilon the check finds with 80% power. It is a statement about E under this pair only.

What a pass means. For S1, S2 and S3 a pass means that for E under the stated pair the empirical epsilon is not above the claim by more than about the stated excess. It does not cover other events, such as the selected set under other pairs, the release values, a larger d or n, or inputs with values between 0 and gamma. The true epsilon of the whole filter is the largest over all events and all neighbouring pairs, so the checked quantity is a lower bound on it.

## Decision thresholds

1. A row holds when LB is at most the claim. An excess is found when LB is above the claim.
2. A null result counts as informative only when its excess at 80% power is at most half of the claim. Otherwise it is reported as uninformative whatever the lower bound is.
3. A numeric prediction holds when the observed value is inside the stated tolerance. A prediction that does not hold stays in the record as written.
4. A positive control passes when LB is above 0.1 times the claim.
5. V holds when all six file hashes agree with each other and with the 2.9.1 hashes above and the three seeded digests agree for each filter. Any difference is reported with both hashes and a diff of the two files.

## Stopping rule

N is fixed at 500,000 per world and per row. There are no interim looks, no extra seeds and no change of configuration after the first full run. If any LB is above its claim, one replication runs with fresh seeds (the block seeds above plus 5,000,000) and both results are reported. An excess is called found only when both runs show LB above the claim. The replication is the only run that may be added.
