# v0.16.10 P3b Colab runbook: plaintext baseline gate, then aggregate and collusion

Pre-registration: `docs/preregistration/v0.16-p3b.md`. Script: `scripts/p3b_breaching_cifar10.py`, SHA-256 `f2e575d882e0c1ea0fd33696af089410f0d4fb49479a44c26d22c2280c947a02`.
Target runtime: Colab with a Tesla T4 (15 GB), torch and a matching torchvision preinstalled. Do not reinstall torch.

Nothing in this runbook changes a pre-registered parameter. The flags that matter for the real run are `--out`, `--data-dir`, `--data-source hf`, `--seeds 20` and `--device cuda`. Do not pass `--quick` for the real run, because a quick run writes no verdicts. The script has no flag for sizes, grids or margins.

Results of this run are not yet written. This file only says how to run it.

## What you need

* The script file `scripts/p3b_breaching_cifar10.py` from this repository, at the commit that holds the pre-registration and the script.
* A Google Drive folder for the output, `MyDrive/feddisclosure_p3b`. Seed files are written there one at a time, so a disconnect loses at most the seed in progress.
* Optional but preferred: the model file of P3, `MyDrive/feddisclosure_p3/out/model.pt` (SHA-256 of the state `66ef08e119ed94103d24384e1dc39044cafb45d5858c04cca99a1b1b4b264891`). With it, the two studies use the same global model. Without it the script trains a model with the P3 recipe, which on another GPU gives a slightly different model. If the file is present but was trained with a different configuration (for example another data source), the script stops with a message and does not retrain. The log and every JSON say which model was used, and the first lines of the full run must read `same as the P3 checkpoint: True` when the P3 file was copied.
* About 700 MB of local disk on the runtime for the CIFAR-10 download and cache. It goes to `/content`, not Drive.

**7. Look at the result.** Use this cell for a complete 20 seed run. It also works on a partial run (at least 2 seed files), where it prints the withheld verdicts, and it stops with a message when `summary.json` is missing.

```
import json, os
d = '/content/drive/MyDrive/feddisclosure_p3b/out'
assert os.path.exists(d + '/summary.json'), 'no summary.json yet (needs at least 2 seed files)'
s = json.load(open(d + '/summary.json'))
print(s['status'])
for k, r in s['rows'].items():
    g, q = r['gain_psnr_db'], r['gain_ssim']
    print(f"{k:16s} PSNR gain {g['mean']:+6.2f} [{g['lo']:+6.2f}, {g['hi']:+6.2f}]  SSIM gain {q['mean']:+.3f} [{q['lo']:+.3f}, {q['hi']:+.3f}]  attack {r['attack_mean_psnr']:.2f} floor {r['floor_mean_psnr']:.2f}")
for k, v in s['verdicts'].get('withheld', s['verdicts']).items():

pc = s['power_check_observed_vs_assumed_sd']
print(len(pc), 'power entries, void (observed sd above 1.5 times the assumed one):', [k for k, e in pc.items() if e['power_void']])
print(json.load(open(d + '/tuning.json')))
```

Expected status: `verdicts computed`. Any other status names the reason (for example fewer than 20 seeds). A row whose gate failed prints as NOT INTERPRETABLE with the gate that blocked it. That is the intended result of the gate and not an error. Read the pre-registration reporting rules before describing it.

## Where the files land

All in `/content/drive/MyDrive/feddisclosure_p3b/out/`:

| File | Content |
|---|---|
| `model.pt` | the shared CNN checkpoint, its SHA-256 and held-out accuracy |
| `tuning_seed9100.json` to `tuning_seed9102.json`, `tuning.json` | PSNR of every grid point and the selected total variation settings, with a flag for a winner at the edge of the grid |
| `seed100.json` to `seed119.json` | one file per evaluation seed, per image MSE, PSNR and SSIM for the 7 rows, the label-only floor attached to every row, the script SHA-256, host name and start time of the runtime |
| `images_seed100.npz`, `images_seed101.npz` | originals and reconstructions of the first two seeds, for a visual check |
| `summary.json` | seed-level bootstrap intervals in both metrics, the gates K0, G4P, G4S, G2P, G2S, the rules C, Q, A and D per arm and metric (NOT INTERPRETABLE where the gate failed), T1, and the observed seed standard deviation next to the assumed one |

The CIFAR-10 cache stays in `/content/p3b_data` and is lost with the runtime. The model and tuning files are on Drive, so a resumed run does not retrain or retune.

## Resuming after a disconnect

Run cells 1, 2, 3 and 4 again, then run the cell 6 command unchanged. The script skips every seed whose JSON is present and complete, reuses `model.pt` and `tuning.json`, and redoes a seed whose file is missing or was cut off. A seed file written under different settings is refused with a message, and in that case use a new `--out` folder. Do not delete `model.pt` or `tuning.json` between sessions. Each seed file records the script hash, host name and start time of the runtime that wrote it. Write the runtime change in the deviation log of the pre-registration.

To rebuild only the summary from the existing seed files:

```
!python /content/p3b_breaching_cifar10.py --stage summarise --seeds 20 --out /content/drive/MyDrive/feddisclosure_p3b/out
```

## Runtime estimate

The estimate uses the P3 timings on the T4 (about 7 ms per attack iteration, whatever the batch, which P3 measured as 28 seconds for 4,000 iterations). The P3b run was not timed on a T4 and the figure below is an assumption until the first seed finishes.

| Item | Count | Time at 7 ms per iteration |
|---|---|---|
| Setup, install, data download and parse | once | about 5 minutes |
| Model training (skipped when the P3 model is copied) | once | 1 to 2 minutes |
| Tuning | 3 seeds x 3 views x 4 grid values = 36 attacks of 4,000 iterations | about 17 minutes |
| Evaluation | 20 seeds x 7 attacks of 4,000 iterations = 140 attacks | about 65 minutes (196 seconds per seed) |
| Total | | about 88 minutes |

At 6 ms per iteration the total is about 76 minutes, at 8 ms about 100 minutes. On the 2 vCPU CPU container used for the smoke test one iteration took 7.5 to 14 ms, so the same run on CPU would take about 2 hours of evaluation alone and is not intended. Free Colab sessions may end before this, so expect to resume once.

## After the run

2. Do not edit any seed file. If something needs a correction, add a dated entry to the deviation log of `docs/preregistration/v0.16-p3b.md` and report both outcomes.

## Known risks on the GPU run

* The Colab stack was not available when the script was tested. The library uses `torch.jit.script` in its objectives. If cell 5 fails inside `breaching`, copy the traceback and stop before the full run.
* `breaching` returns whatever it has when its objective turns non-finite. The script counts these in `invalid_reconstructions` and does not retry.
* GPU results are not bitwise reproducible. A rerun can differ in the last digits.
* If the P3 model file is copied, the script refuses it when its training configuration differs (for example when the data source was not `hf`). Use `--data-source hf` as in cell 6.
* If the total variation winner sits at an edge of the grid (0.05 or 3.2), the report says so and the grid is not extended.
