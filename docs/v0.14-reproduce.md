# Reproducing v0.14 results

Requirements: Linux with Docker Engine 29 and Compose v2, Python 3.12, about 8 GB RAM, no GPU. Pinned versions that matter: Flower 1.27.0, torch 2.5.1 (CPU, must match the container image), opacus 1.6.0, opendp 0.16.0.

## Environment

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e .
pip install --index-url https://download.pytorch.org/whl/cpu 'torch==2.5.1' 'torchvision==0.20.1'
pip install 'flwr==1.27.0' opacus==1.6.0 opendp==0.16.0 python-pptx
export PYTHONPATH=src:.
```

Installing the `research` or `opacus` extras can pull a CUDA torch build. If that happens, uninstall torch, torchvision and triton and reinstall the CPU pins above, then `pip install --no-deps` for anything else.

If your network re-terminates TLS, point Docker builds at your CA bundle with `export FDL_BUILD_CA_BUNDLE=/path/to/ca-bundle.crt`. Never disable verification.

## MNIST

Place the two pinned MNIST train files in `data/source/mnist/` (checksums in `docs/data-provenance.md`). The loader refuses any file whose SHA-256 differs.

## Phase 1: native Docker + Flower

```bash
bash scripts/run_native_scenarios.sh            # repeat, non-IID, fault scenarios, parity
python scripts/summarize_native_scenarios.py
# Full MNIST, 10 rounds
python scripts/run_flower_docker.py --config configs/training/fedavg_mnist_full_native.yaml \
  --data-dir data/training/mnist-full-docker-iid-v014 --run-dir reports/results/native_flower/v014/run-mnist-full-iid \
  --env-file /tmp/run-mnist-full-iid.env --timeout 1500
R=reports/results/native_flower/v014/run-mnist-full-iid; D=data/training/mnist-full-docker-iid-v014
python scripts/run_torch_reference.py --config configs/training/fedavg_mnist_full_native.yaml --data-dir $D --output $R/torch_reference.json
python scripts/verify_flower_parity.py --flower-dir $R/server --reference-json $R/torch_reference.json \
  --reference-checkpoint $R/checkpoints/mnist-full-iid-native-v014_final.pt --manifest $D/manifest.json \
  --output $R/flower_parity.json --require-deployment
```

Each run writes `docker_topology.json`, `client_attestations.json`, `flower_parity.json` and logs. A run counts only if all of these pass.

## Phase 2

```bash
bash scripts/run_secagg_scenarios.sh && python scripts/verify_secagg_native.py
python scripts/run_opendp_study.py

python scripts/run_opacus_dp_sgd.py --data-root data/training/digits-docker-iid-v012 --client-id 0 \

```

## Tests, dashboard, deck

```bash
pytest -q -m 'not slow'
python -m dashboard.build_dashboard          # dashboard/dist/index.html
python scripts/build_faculty_briefing_v014.py # reports/faculty-briefing-v0.14.0.pptx
```

The dashboard and deck read only saved evidence and refuse to build the v0.14 sections if it is missing.

## Time on the reference machine

Digits native run about 1 to 2 minutes. MNIST native run 238 s. SecAgg+ scenarios 25 to 175 s each. Digits Opacus study a few minutes. MNIST Opacus study about 15 minutes.

## Known gaps

Hosted CI was not run. Fault handling waits for a timeout. SecAgg+ was only run with 3 clients. See `docs/v0.14-privacy-secagg-results.md`.
