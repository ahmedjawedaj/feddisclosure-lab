# v0.8 protocol: aggregate-only observations, collusion, and native local DP-SGD

November 19, 2026. Planned before interpretation. All data are approved public sklearn 8×8 digits.

## Experiment A: aggregate vs individual update, five seeds

**Hypothesis:** an attacker targeting institution A with its label vector available will reconstruct A's eight private image features more accurately if it sees A's *individual* update than if it sees only the arithmetic mean of updates from A, B and C. A coordinator colluding with B and C can algebraically recover A's update from the mean, restoring access. This is a controlled *observer-capability* demonstration, not cryptographic secure aggregation or a proof of protection.

**Setup:** three nonoverlapping public-data institutional partitions from `data/training/digits-iid`; 8 sampled distinct records per client, one full-batch SGD step, lr=0.15, 64-feature DigitMLP, shared seeded initial weights, equal update weights. Seeds 241–245 fixed before experiments, 160 optimization steps using the same attack seed +1. No changed minibatches or additional training epochs. Total target = 8 images. Attack uses initial weights, known local step hyperparameters, **privileged known target labels**, and one role-allowed model delta. Attack never reads target image pixels or evaluator matching assignments.

**Three attacker roles:**

1. `individual`: server sees the raw individual update of target A.
2. `aggregate_only`: server sees only `(ΔA + ΔB + ΔC)/3`; it runs the *same target-only* gradient-proxy attack against this aggregate. This is a **misspecified** target model, not an optimal aggregate attack. It cannot infer the other two images, their labels, their contribution sizes or exact update vectors.
3. `all_but_one_collusion`: server sees the mean and B and C individual updates, then isolates A by `ΔA = 3 mean − ΔB − ΔC`. No cryptographic scheme is implemented or bypassed. This role represents a confidentiality failure if all other contributors disclose their updates and the unmasked aggregate is available.

**Ground truth boundary:** setup creates the real model updates from local public-data examples and puts observation files in case-specific `attacker` directories; target pixels and original indices are written only to `evaluator_only`. Python modules and subprocess contracts separate attack and evaluation. They still share the same OS user and disk, so this is not hardened filesystem isolation.

**Metric:** evaluator-only Hungarian image matching on 8 target images, mean pixel MSE, mean PSNR, mean SSIM; average and sample SD over five independent sampling/model seeds. Explicitly save unsuccessful attacks. Save hash of observations, recovered images, evaluation JSON, target truth. A successful collusion isolation must match individual deltas with max tensor error below 2e-6. No claim that MSE directly measures legal/sensitive information leakage.

**Reproduce:**

```bash
for seed in 241 242 243 244 245; do
  python scripts/run_aggregate_collusion.py --data-root data/training/digits-iid \
    --output-dir reports/results/sprint4/aggregate_collusion/seed${seed} \
    --seed "${seed}" --examples 8 --iterations 160
done
python scripts/verify_aggregate_collusion.py
python scripts/plot_aggregate_collusion.py
```

Existing experiment directories are never overwritten.

## Experiment B: native single-silo Opacus DP-SGD vs SGD

**Hypothesis:** real per-example gradient clipping and Opacus-calibrated Gaussian noise will change utility, and its native accountant will report an actual `(epsilon, delta)` bound for *one local training invocation*, under the documented Poisson sampling assumptions.

**Protocol:** one public digit site, initial weights shared between standard SGD and native Opacus DP-SGD, 2 nominal epochs, batch size 32, lr=0.15, clip 1.0, epsilon target 5.0, delta 1e-5, Poisson sampling, RDP accountant, `secure_mode=False`. Save only final model checkpoints, evaluator-only held-out public accuracy/loss, actual epsilon, delta, noise multiplier, number of steps and explicit library status. Because Poisson training changes realized batches, this is a nominal-budget comparison, not an exact step-for-step match. No cross-client or cross-round privacy accounting is asserted.

**Hard gate:** importing Opacus, executing the real private optimizer, passing `PrivacyEngine.get_epsilon(delta) <= target`, and successfully completing the evaluator subprocess. If Opacus is absent or accounting fails, **write no success JSON** and report native acceptance blocked. Do NOT substitute handcrafted noise. Use the `opacus-native.yml` GitHub workflow on a network-enabled Python 3.12 runner.

```bash
python -m pip install -e '.[privacy,research,test]'
python scripts/prepare_fl_data.py --output data/training/ci-public-digits --limit 600 --seed 20261118
python scripts/run_opacus_dp_sgd.py --data-root data/training/ci-public-digits \
  --output-dir reports/results/sprint4/opacus_native --epsilon 5.0 --delta 1e-5 --epochs 2
```

**Not implied:** a local DP-SGD mechanism protects neither raw analytical query releases nor unprotected updates sent elsewhere; it is not a Flower multi-client run. The repeated participation/composition challenge remains open.
