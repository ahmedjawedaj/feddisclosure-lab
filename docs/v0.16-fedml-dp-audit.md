# v0.16 P2: measured privacy of FedML's differential privacy mechanisms

Status: not peer reviewed, not yet part of a release. Draft for integration.
Pre-registration: `docs/preregistration/v0.16-fedml.md` (committed before any mechanism was executed).
Evidence: `reports/results/privacy/v0160/fedml_dp_audit/fedml-0.9.6/fedml_dp_audit.json`.
Harness: `scripts/audit_fedml_dp.py`. Tests: `tests/privacy/test_audit_fedml_dp.py`.

## Summary

The harness runs the real classes under `fedml/core/dp` of `fedml` 0.9.6 in process and compares the mechanism that executes with the one implied by the configured parameters. FedML's own `__init__` was never executed and no network call was possible during the runs. The DP source files are byte-identical in the seven earlier releases that were downloaded and compared, from 0.8.4 (June 2023) to 0.9.5, so the numbers describe the DP code of every release checked.

130 programmatic checks encode the pre-registered predictions. 128 held and 2 did not (see Predictions).

1. The Gaussian and Laplace mechanisms deliver the noise scale their formulas give, within 0.5% in all 18 cells measured. At the tested settings both meet their configured (epsilon, delta) guarantee, the Gaussian one conservatively. The Gaussian class refuses epsilon above 1, the range where the classical calibration is not proved.
2. `sensitivity` is one argument for both mechanisms. The Gaussian class needs an L2 bound and the Laplace class needs an L1 bound. With an update of L2 norm 1 spread over 16 coordinates and `sensitivity` set to 1, the executed Laplace mechanism is epsilon 4.00 where the configuration implies 1.00. This is a configuration note and not a property of the mechanism.
3. `LocalDP` adds noise whose scale does not depend on the input and does no clipping. `max_grad_norm` has no effect on it. With `sensitivity` 2, epsilon 1 and updates of norm 1, 5 and 25, exact epsilon is 0.751, 4.54 and 34.5. The empirical bound certifies 0.17, 1.17 and 10.57.
4. `GlobalDP` adds the configured noise when its accountant is off. With `enable_rdp_accountant` true, construction raises `TypeError` because `RDP_Accountant` is called without `dp_param`.
5. `DP_Clip.compute_noise` divides its stored scale by `qw` on every call, so the k-th call has sigma z C / qw^k. `DP_Clip.add_global_noise` returns `None` and leaves the input divided by `qw` with no noise in it. The class is not selected by either call site in the aggregator or the trainer, so it is reached only by direct calls.
6. `RDP_Accountant.get_epsilon` raises after the first `step` in all three configurations tried (a `NameError` for fractional orders with sampling rate below 1, a `TypeError` otherwise). The conversion function underneath, reached through the class, gives epsilon 7 to 9% above the exact Gaussian value, and `compute_rdp` agrees with numerical integration to 1.5e-12.

FedML ships no documentation text for these parameters in the wheel. "Claimed" below means the reading implied by the class docstrings and the cited papers, stated per row. These are measurements under stated configurations and not statements about intended use.

## Setup

16 float32 parameters, delta 1e-5 unless stated, seeds fixed in the script. Sigma and scale are measured over 20,000 independent rows of one batched call to the shipped mechanism (320,000 values). Exact (epsilon, delta) follows from Balle and Wang (2018) for the Gaussian and from the tight Laplace profile delta(eps) = 1 - exp((eps - eps_pure) / 2) for the Laplace. The empirical column is a 95% Clopper-Pearson lower bound on epsilon from 200,000 trials per world with a threshold fixed from the predicted law before the trials. It cannot certify more than about 10.9 at this trial count and has no power when mu is below about 0.5.

Local DP uses replace-one adjacency between +a e1 and -a e1. The per-cell noise draws are independent (one seed per cell). Column correlations and lag-1 correlation of the draws stayed below 0.02 and the Kolmogorov-Smirnov p-values were 0.15 or higher in every Gaussian and Laplace cell.

## Gaussian mechanism (G1, G2)

Claimed reading: (epsilon, delta)-DP for a query of L2 sensitivity `sensitivity` by sigma = sqrt(2 ln(1.25 / delta)) * sensitivity / epsilon. Sensitivity 1 in every cell. The measured sigma is the formula within 0.16%.

| delta | epsilon | sigma formula | measured / formula | mu | exact delta / configured | exact epsilon at configured delta | meets |
|---|---|---|---|---|---|---|---|
| 1e-5 | 0.1 | 48.4481 | 0.9984 | 0.0207 | 0.00027 | 0.061 | yes |
| 1e-5 | 0.5 | 9.6896 | 1.0000 | 0.1032 | 0.00161 | 0.353 | yes |
| 1e-5 | 1 | 4.8448 | 1.0004 | 0.2063 | 0.00407 | 0.751 | yes |
| 0.1 | 0.1 | 22.4754 | 0.9992 | 0.0445 | 0.00201 | 0.000 | yes |
| 0.1 | 0.5 | 4.4951 | 0.9991 | 0.2227 | 0.01220 | 0.000 | yes |
| 0.1 | 1 | 2.2475 | 1.0001 | 0.4449 | 0.03063 | 0.213 | yes |

delta 0.1 with epsilon 0.1 is the configuration in the package's own test file. The code accepts epsilon 1.0 and raises `ValueError("Epsilon cannot be greater than 1. ")` for 1.0000001, 2, 5 and 10. This differs from the Flower local DP rows, where epsilon up to 20 was accepted and fell short above 5. In FedML the classical calibration cannot be configured outside the range where it is proved. The empirical test has no power at these mu values, so the claim rests on measured sigma and the exact formula, as in the Flower audit.

The measured scale is within 0.5% of the formula in every cell. When delta is above 0 the scale is smaller than sensitivity / epsilon, so the executed mechanism is epsilon - ln(1 - delta) pure DP. That is slightly more than the configured epsilon, but the exact delta at the configured epsilon is 1 - sqrt(1 - delta), about half the configured delta, so the (epsilon, delta) claim holds. A meets verdict in this table uses the formula scale. The exact delta computed from the measured scale at epsilon 5 and delta 0 (0.0123) reflects a 0.5% sampling error in the scale and not a property of the mechanism.

LP2 (configuration note). One `sensitivity` argument feeds both classes. With it set to 1 as an L2 bound on the update, epsilon 1 and delta 1e-5:

| Update (L2 norm 1) | L1 norm | pure epsilon implied by the configuration | pure epsilon executed | empirical lower bound |
|---|---|---|---|---|
| all mass on one coordinate | 1 | 1.00001 | 0.9999 | 0.985 |
| equal mass on 16 coordinates | 4 | 1.00001 | 3.999 | 2.79 |

The Laplace class is correct for its L1 reading. The factor is sqrt(d) for an evenly spread update, here 4 for d = 16. A user who has an L2 clipping bound and passes it unchanged as `sensitivity` gets epsilon sqrt(d) times larger than configured, in the worst case. Issue 1586 in the FedML tracker shows a user asking how to set this value.

LP3 (observation). `add_noise` returns float32 for the Gaussian and float64 for the Laplace on float32 input (the Laplace noise is a numpy float64 tensor). An int64 buffer comes back as a floating tensor in both.

## Clipping and noise frame, `DP_Clip` (K1 to K4)

The module docstring cites McMahan et al. (2018): clip each update, add Gaussian noise to the average estimator. Configuration used: C 1, z 1, 1,000 training samples, 10 of 100 clients per round, so `qw` = 100.

K1. `clip_local_update` bounds the total L2 norm. Inputs of norm 5 and 50 come out at 0.99999981 and 0.99999998 (the helper adds 1e-6 to the norm), norm 0.5 is unchanged, and the input tensors are modified in place. `add_local_noise` adds no noise. It subtracts the global parameters and clips, and its output is identical for different seeds.

K2. `compute_noise` divides its stored scale by `qw` on every call.

| Call | Stored scale after the call | Measured sigma | Predicted z C / qw^k |
|---|---|---|---|
| 1 | 1e-2 | 0.01002 | 1e-2 |
| 2 | 1e-4 | 9.99e-05 | 1e-4 |
| 3 | 1e-6 | 9.98e-07 | 1e-6 |
| 10 | 1e-20 | within 0.5% | 1e-20 |
| 22 | 1e-44 | 9.79e-45 (94% of values nonzero) | 1e-44 |
| 23 | 1e-46 | 0 (all values zero) | 1e-46 |

Inside one `add_noise` the first tensor of the model gets z C / qw and the second z C / qw^2. The state carries over to the next round, so the first tensor of round 2 got 1.0e-06 and the second 1.0e-08 (measured). With a model of 23 or more tensors the noise is exactly zero for the later tensors in the first round. The single-release reading of the docstring (mu = 1 / z) matches only for the first tensor of the first call.

K3. `add_global_noise` returns `None`. After the call the input dict holds the original values divided by `qw` (largest deviation 7.5e-10) with no noise in it. The noised dict is built and discarded.

K4. After `FedMLDifferentialPrivacy.init` the predicates the call sites use read as follows.

| `dp_solution_type` | frame | local DP enabled | global DP enabled | clipping |
|---|---|---|---|---|
| ldp | LocalDP | true | false | false |
| cdp | GlobalDP | false | true | true |
| dp_clip | DP_Clip | false | false | false |

`client_trainer.py` calls the frame only when the local predicate is true and `server_aggregator.py` only when the global predicate is true. So `DP_Clip` is not called through them in 0.9.6. K2 and K3 describe the class when called directly.

## Central DP frame, `GlobalDP` (CD1 to CD3)

CD1. With the accountant off, `GlobalDP.add_global_noise` adds Gaussian noise whose sigma is 0.48467 against a formula value of 0.48448 for sensitivity 0.1, epsilon 1, delta 1e-5 (ratio 1.0004). `is_rdp_accountant_enabled` exists and is False because `BaseDPFrame.__init__` sets it, so reading it raises nothing. The candidate that said it is set only inside an `if` is refuted. `GlobalDP` sets a different attribute `enable_rdp_accountant` that nothing in the frames reads.

CD2. With `enable_rdp_accountant` true, `GlobalDP(args)` and `FedMLDifferentialPrivacy.init(args)` both raise `TypeError: RDP_Accountant.__init__() missing 1 required positional argument: 'dp_param'`. The accountant cannot be switched on through the frame.

CD3. With `max_grad_norm` 1 the clip helper returns norms 0.5, 0.999999 and 0.999999 for inputs of 0.5, 3 and 30, and modifies the large ones in place. The helper repeats the clip once per key, which accounts for the 1e-6 shortfall. With `max_grad_norm` unset it returns the same list unchanged, so nothing bounds a client's contribution. The server calls it on the client model list, which holds model weights in the default FedAvg flow and not updates.

## Local DP, `LocalDP` (LD1, LD2)

`sensitivity` 2, epsilon 1, delta 1e-5, so sigma is 9.69 and the measured sigma is within 0.3% of it. The noise does not depend on the input. Replace-one sensitivity is 2a.

| Update norm a | Replace-one sensitivity | mu | Exact epsilon at 1e-5 | Empirical lower bound | Meets (1, 1e-5) |
|---|---|---|---|---|---|
| 1 | 2 | 0.206 | 0.751 | 0.172 | yes |
| 5 | 10 | 1.033 | 4.54 | 1.17 | no |
| 25 | 50 | 5.15 | 34.5 | 10.57 | no |

The output mean equals the unclipped input. LD2 sets `max_grad_norm` 1 and gets output identical to LD1 for a = 25 under the same seed, because `LocalDP.add_local_noise` calls only the noise step and `max_grad_norm` is read only by `global_clip`, which the server calls for central DP. The guarantee therefore holds only if the user sets `sensitivity` to the true replace-one change of whatever is sent, and nothing in the frame enforces a bound. The a = 25 case is deliberately large, and real update norms were not measured.

## RDP accountant (RA1 to RA5)

RA1. `get_epsilon(delta)` before any step returns the tuple `(0, 0)`. After one `step`:

| Sampling rate, orders | Outcome |
|---|---|
| 0.1, default orders (90 fractional, 61 integer valued) | `NameError: name '_log_erfc' is not defined` |
| 1.0, default orders | `TypeError: RDP_Accountant.get_privacy_spent() takes 0 positional arguments but 1 positional argument (and 3 keyword-only arguments) were given` |
| 0.1, integer orders only | the same `TypeError` |

`rdp_analysis.py` calls `_log_erfc` for fractional orders and the name is not defined in the module, so any sampling rate below 1 with the default order list fails first. At sampling rate 1 or with integer orders the failure is `get_privacy_spent`, which is declared keyword-only without `self` and is called as a method. Two equal steps merge into one history entry with two steps in all three cases.

RA2. Calling the conversion function through the class, full participation, one step, delta 1e-5:

| sigma | Shipped epsilon | Exact epsilon | Ratio |
|---|---|---|---|
| 0.5 | 10.726 | 9.997 | 1.073 |
| 1 | 4.729 | 4.377 | 1.080 |
| 2 | 2.166 | 1.993 | 1.087 |
| 4 | 1.013 | 0.926 | 1.093 |

RA3. `compute_rdp` at integer orders 2, 4, 8, 16 for sampling rates 0.01 and 0.1 and sigma 1 and 2 agrees with numerical integration of E[(mu1 / mu0)^alpha] with a worst relative difference of 1.5e-12.

RA4 (hypothetical, because CD2 prevents reaching it). `Gaussian.get_rdp_scale()` returns sigma itself, and the Laplace version returns scale divided by sensitivity. The frame passes this as `noise_multiplier`. For the Gaussian the true multiplier is sigma / sensitivity, so the two agree only when sensitivity is 1. With epsilon 1 and delta 1e-5, one full-participation step:

| `sensitivity` | Value passed | True multiplier | Epsilon the accountant would report | Exact epsilon |
|---|---|---|---|---|
| 0.1 | 0.484 | 4.845 | 11.15 | 0.751 |
| 1 | 4.845 | 4.845 | 0.822 | 0.751 |
| 10 | 48.45 | 4.845 | 0.116 | 0.751 |

RA5. For the Laplace mechanism `get_epsilon` raises `TypeError: unsupported operand type(s) for /: 'float' and 'NoneType'` because the branch passes `rdp_scale=None`. It raises before any step as well as after.

## Observation (OB1)

The package's own test file `core/dp/test/test_fed_privacy_mechanism.py` builds arguments without `dp_solution_type` and calls `add_noise` on `FedMLDifferentialPrivacy`. `init` with those arguments raises `AttributeError` for `dp_solution_type`, and the class has no `add_noise` method in 0.9.6.

## Limits

1. One framework version. The DP tree is identical in the seven earlier releases compared, but only 0.9.6 was run. Releases 0.8.0, 0.8.2, 0.8.3, 0.8.7 and others between those listed were not compared.
2. The harness calls mechanism and frame classes directly. It does not run a deployment, an aggregator, or FedML's `init`, so it says nothing about which configurations occur in practice. The K rows and RA rows describe classes that the call sites do not reach or cannot construct.
3. No aggregation was executed. Central sensitivity, client weights, unequal result counts and sampling were not measured. The weight effect measured for Flower (rows C3 and C4) was not repeated for FedML, so no cross-framework comparison of it is made here. The accountant's sampling model (a rate of clients per round over clients in total) was not compared with how FedML samples clients.
4. "Claimed" is the textbook reading from class docstrings and cited papers. The wheel has no DP documentation. FedML's online documentation was not consulted, so a documented setting that differs from these readings would change the verdicts in LP2, LD1 and RA4.
5. Release notes were not read. The GitHub releases endpoint returned HTTP 403 and was not retried. Tracker issue comments were not read. No literature search was repeated in this step.
6. The environment reuses numpy 2.5.3, scipy 1.18.1 and torch 2.15.0 from the system and does not satisfy FedML's declared `numpy<2`. The DP modules use only basic numpy and torch calls, but they were not run on FedML's declared versions.
7. Floating-point effects in the sampling of noise (finite precision in float32 and float64 draws) were not examined. The NbAFL frame and the homomorphic encryption path are outside this audit.
8. LD1 uses toy updates of norm 1, 5 and 25 along one axis. K2 uses one configuration of `qw`. The Laplace tests use one adjacent pair per case.
9. The harness was written after the pre-registration commit and in the same working session. Predictions were written from code reading before any mechanism was executed. Development used quick runs after that commit (see the deviation log).

## Deviation log

Nothing in the pre-registration was edited after the runs.

1. Environment. The virtual environment was created with `--system-site-packages` to reuse the installed numpy, scipy and torch. The pre-registration states this. `fedml` is installed only in the environment. Its wheel hash matches PyPI.
2. Quick runs during development. After the pre-registration commit the harness was run in quick mode (500 draws) several times before the full run. The first quick run showed these harness issues, which were fixed before the full run. Nothing in the predictions was changed. (a) Cells of G1 and LP1 shared a seed by epsilon, so each cell now has its own seed. (b) The check for reads of `enable_rdp_accountant` also matched `hasattr(args, ...)` and was narrowed to `self.enable_rdp_accountant`. (c) The LP1 "meets" verdict compared the exact delta from the measured scale with a threshold of zero for delta 0, which a 0.5% sampling error always fails. It now uses the exact delta from the formula scale and adds a separate within 2% check on the measured pure epsilon. (d) RA1 was a single case. The first quick run showed a `NameError` where a `TypeError` was predicted, so it was extended to the three cases in the table. The pre-registered prediction is scored as written against the sampling-rate-0.1 case.
3. Quick-mode statistical checks (sigma within 1%) fail at 500 draws by construction. Only the full run is evidence. The test suite asserts the deterministic checks in quick mode.
4. Math functions are copied from `scripts/audit_flower_dp.py` and not imported, so the harness needs no Flower install. A test compares their syntax trees with the Flower script.
5. Central rows were not run with zero-out adjacency on an aggregate. The pre-registration listed zero-out for central rows, but no aggregation code was executed, so CD1 and CD3 measure the noise path and the clip helper only. Replace-one was used for LD1 as planned.
6. LP2 and the other Laplace rows used a threshold from a numpy simulation of the predicted law (seed 7, 400,000 draws per world), as pre-registered.
7. GitHub release notes could not be read (HTTP 403, not retried).
8. Prediction failures are listed under Predictions.
