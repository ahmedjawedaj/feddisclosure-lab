# v0.9 execution and reproducibility protocol

1. Read `AGENTS.md`, `CURRENT_STATE.md`, `NEXT_SPRINT.md`, `docs/threat-models.md` and `docs/v0.9-results.md`.
2. Use only the pinned public digit partitions in `data/training/digits-iid`. They must contain disjoint institutional source indices. Do not connect real patient or private datasets.
3. For a new joint attack run, choose a new empty output directory and seed: `python scripts/run_joint_aggregate_attack.py --seed 244 --iterations 160 --output-dir reports/results/sprint4/joint_aggregate_oracle/seed244`.
4. The setup and evaluator have privileged access to synthetic/public truth. The attacker sees aggregate update and all contributor labels in institution-grouped order. Do not use original image files to tune the attacker mid-run.
5. After completing a new seed, extend the explicit seed list in `scripts/verify_joint_aggregate.py` (and test) and rerun verification. Never silently overwrite earlier observations.
6. Export dashboard: `python -m dashboard.build_dashboard` and open `dashboard/dist/index.html`. It is read-only and contains only scalar data.
7. Validate the stored original five-seed training comparison: `python scripts/analyze_balanced_study.py`. Interpret wide paired intervals and sign-flip p-values as exploratory.
8. Run tests `PYTHONPATH=src:. pytest -q -m 'not slow'`. Run subprocess integration tests separately on an adequate host. Run native DP/Flower/Docker only where dependencies are actually installed.
9. Retain raw experimental input/output outside Git. Commit curated reports and code, preserve the complete evidence in an archive, and update the handoff on every milestone.
